# Интерфейс SmartSQL

Общая оболочка WorkspaceWindow использует семантические серую/светлую темы, зелёный акцент, мягкие границы и векторные иконки. Таблица занимает основную площадь. Интерфейс сначала развивается на русском: слева — общее дерево подключений, в центре — вкладки проектов, обычных таблиц и SQL. Сверху справа закреплены выбор темы и Simple/Advanced; выбор сохраняется атомарно. Нативные кнопки управления окном включены явно, пользователь подтвердил их возвращение. Полная визуальная и доступностная приёмка остаётся открытой; единый план — [WORK_PLAN M02/M10](WORK_PLAN.md).

- **Простой режим**: редактирование ячеек с автоматическим сохранением, новые записи, импорт XLSX, вставка из Excel, все форматы обмена, поиск, фильтры, сортировка и отмена последнего изменения ячейки.
- **Расширенный режим**: те же данные и повседневные действия, плюс SQL, подробная структура и дополнительные инструменты по возможностям провайдера. Сохранённые managed-фильтры уже реализованы. Переключение не сбрасывает таблицу или применённые условия и не меняет права базы. Интегрированного ИИ пока нет.
- **Подключения PostgreSQL**: общий обозреватель в центральных вкладках, данные/структура, буквальный поиск, типизированные AND-фильтры и нативная сортировка до пагинации. По умолчанию — чтение; явное разрешение на сессию включает изменение одной ячейки по ключу для поддерживаемых объектов/полей. Диалоги записи ещё требуют оставшегося ручного прогона сценария.
- **Новая запись PostgreSQL**: отдельная форма DEFAULT/NULL/значения по подтверждённым INSERT-возможностям; серверные identity/generated поля защищены, результат COMMIT и загрузка страницы обозначаются отдельно.
- **Удаление строки PostgreSQL**: отдельные DELETE-возможности и подтверждение базы/схемы/таблицы/PK/данных. Кнопка доступна только для подтверждённой строки; входящие FK пока запрещены. После ошибки нужна новая загрузка, неизвестный COMMIT не повторяется автоматически. Ручная приёмка нового диалога остаётся открытой.
- **Обычный SQLite**: команда **SQLite…** открывает тот же обозреватель с корректной подписью SQLite и локальным файлом, без имитации серверного профиля. Чтение не требует метаданных SmartSQL. Отдельный opt-in включает ограниченное изменение одной ячейки с обязательной проверенной копией до записи; native INSERT/DELETE пока недоступны.
- **SQL и инспектор**: независимые вкладки ограниченного SQL только для чтения, локальная ограниченная история, UTF-8 файлы, подсветка, отмена и восстановление сессии. Отдельный инспектор показывает принадлежащие объекту ограничения/индексы/исходные определения с явными границами покрытия; входящие FK/domain constraints/dependency graph этим срезом не реализованы.

Заголовки локальных столбцов сортируют весь набор записей, повторное нажатие меняет направление. Номер слева означает позицию в текущем результате, а не идентификатор записи. Длинные значения PostgreSQL открываются полностью двойным щелчком, с отдельным отображением NULL и пустой строки и кнопкой копирования.

Команды организованы по назначению: **База**, **Импорт**, **Экспорт**, **Структура**. SQL только для чтения уже доступен; будущие ИИ/диаграммы и SQL-запись появятся только вместе с соответствующими рабочими функциями и проверенными ограничениями.

## Как расширять

`Styles/Tokens.axaml` хранит палитру и размеры, `Styles/Controls.axaml` — общие классы оформления, `Styles/Icons.axaml` — нативные векторы. `Presentation/Strings.ru.axaml` содержит статические русские подписи основной оболочки. Список ключей и правила оформления находятся в `src/SmartSQL.Desktop/Presentation/README.md`.

`WorkspaceWindow.axaml` задаёт общую оболочку и вкладки; встроенный managed-редактор сохраняет панели `MainWindow.axaml` и представление `MainWindow.Presentation.cs`. Native-таблицы и SQL используют собственные представления и независимые сессии на вкладку. Обмен, подключения и работа с данными сохраняют отдельные обработчики. Новая кнопка использует существующий стиль и присоединяется к своей группе команд; бизнес-операции остаются в Application/Infrastructure.

Для английского потребуется вынести оставшиеся тексты диалогов/статусов и добавить полный словарь `Strings.en.axaml`. Текущая версия не предлагает частично переведённое переключение языка. Режим выбирается при первом запуске, запоминается и постоянно доступен для переключения.

Все профили, локальные данные и результаты проверок остаются на D:; в Git сохраняются исходники и документация.

Исторические снимки локального редактора до общей оболочки: [простой режим](smartsql-simple-mode.jpg), [расширенный режим](smartsql-advanced-mode.jpg). Они не являются свидетельством приёмки текущего WorkspaceWindow.

## Текущая оболочка и оставшаяся приёмка

При первом запуске пользователь выбирает режим; выбор запоминается, кнопка переключения постоянно доступна. Оба режима используют те же вкладки, подключения и данные. Переключение не даёт права записи и не сбрасывает условия.

Одно основное окно уже объединяет дерево подключений/баз/схем/таблиц слева, вкладки таблиц и SQL в центре, структуру активного объекта и статус подключения. Вкладка хранит свой объект, страницу, запрос и состояние загрузки/ошибки. Одноимённые таблицы разных подключений остаются независимыми; закрытие отменяет и освобождает свою сессию. Точная доводка расположения/сворачивания всех панелей входит в M10, а не считается уже принятой.

Простой режим ведёт через таблицы, фильтры и импорт без SQL; расширенный добавляет SQL и подробную структуру по мере готовности. Приёмка включает обычное/минимальное окно, масштаб 100/150/200%, клавиатуру, возврат фокуса, доступные имена/роли кнопок и таблиц, контраст, текстовые обозначения ошибок/NULL/доступности и короткий сценарий с экранным диктором Windows. Длинные подписи и состояния загрузки/ошибки сравниваются с двумя пользовательскими референсами. Порядок и критерии — в [плане](WORK_PLAN.md).
