# Подготовка нативного инспектора T12

Статус 16 октября 2026: выполнен разбор существующего кода; это план первого среза, не реализованный API или принятый UI. Реализация следует после оставшейся приёмки T11. Управляемый `Domain.TableDefinition` не расширять под внешние объекты: его GUID и локальные типы относятся к проектам SmartSQL. Нативный `DatabaseColumn` уже сохраняет имя, native type, nullable и порядок PK.

## Первый результат

В существующей панели структуры показать реальные столбцы, ключи/ограничения, индексы и доступные нативные определения выбранного объекта PostgreSQL/SQLite. Чтение не зависит от разрешения редактирования. Не добавлять ER-диаграммы, DDL-редактор, изменение структуры или новые разрешения FK-удаления.

Контракт нужно зафиксировать до делегирования реализаций. Предлагается отдельный provider-neutral результат структуры с секциями и явной полнотой `Complete / Partial / Unavailable`; неполная или недоступная секция не должна выглядеть пустой полной секцией. Непрозрачное нативное определение предназначено только для отображения, не исполнения. Нужны nullable неизвестные признаки, порядок колонок/FK-пар/термов индекса и представление неизвестного вида ограничения. Состав полей ограничить первым отображаемым сценарием, не строить модель миграции заранее.

## На что опираться

- PostgreSQL: закрытый fingerprint редактирования уже читает `pg_get_constraintdef`/`pg_get_indexdef`; удаление отдельно обнаруживает входящие FK. Новый read-only инспектор должен читать каталог в одном согласованном снимке и не менять эти write guards. Не терять `NOT VALID`, invalid indexes, deferrability, expression/partial/include indexes, exclusion и неизвестные виды. Domain constraints и внешние зависимости показывать только при подтверждённом scope; если не прочитаны, обозначить ограничение.
- SQLite: код editing metadata уже обращается к `sqlite_schema`, `index_list`, `index_xinfo`, `foreign_key_list`, но отбрасывает часть подробностей. Эти сведения нужно сохранить для отображения. Не писать SQL lexer ради CHECK/имён/deferrability: полного восстановления этих свойств через PRAGMA нет. Сохранить исходный SQL объекта и явно показать частичную структурированную информацию. Имя `sqlite_autoindex` не выдавать за исходное имя constraint; term с `cid=-2` не выдавать за обычную колонку.

Обнаруженная связь не предоставляет права читать связанную таблицу. Размеры метаданных должны быть ограничены с явной диагностикой; ошибка или отмена не оставляет частичный набор, помеченный полным. Права существующего обозревателя и чтение обычных объектов сохраняются.

## Разделение работы

Основной агент фиксирует контракт и интеграцию панели. Независимые владельцы делают PostgreSQL и SQLite в отдельных partial-файлах и реальные provider-тесты; ещё одна проверка сверяет полноту/неизвестные значения и отсутствие влияния на запись. Сборки, полные тесты, документацию и Git выполняет основной агент. Затем ручная приёмка панели на синтетических D:-данных: PK/FK/UNIQUE/CHECK, expression/partial indexes, длинные определения, read-only права, отмена, minimum size/DPI и обе темы. До неё T12 не объявлять закрытой.
