## Использование и контракт

В обычной PostgreSQL/SQLite таблице или представлении включить «Структура» и нажать «Подробнее…». Вкладки: поля, ограничения, индексы, определение/диагностика. Полный текст выделяется/копируется, длинные строки прокручиваются. Каждое открытие читает отдельный согласованный снимок; он может отличаться от показанной страницы. Успешное чтение сохраняет страницу/фильтры/разрешения и handles записи.

Отдельный `Application.DatabaseStructure` не расширяет управляемый `Domain.TableDefinition`: нет навязанных GUID или четырёх локальных типов. Полнота ограничений/индексов — `Complete / Partial / Unavailable` в явно описанном охвате; неизвестные флаги — null. Порядок PK/FK-пар и термов сохраняется; Ordinal индексного терма начинается с 1. Native definition — непрозрачный текст только для показа, без исполнения или подтверждения права изменения.

Охват — собственные ограничения и индексы выбранного объекта. **Входящие FK, domain constraints, зависимости представлений и граф зависимостей не исследуются**, что указано в диагностике/окне. Наличие связи не предоставляет доступ к строкам её назначения. Нет DDL-редактора/ER-диаграммы/изменений структуры. Консервативная политика DELETE со всеми запрещёнными входящими FK сохранена.

Лимиты: 4096 столбцов; по 2000 ограничений/индексов/диагностик; 4096 термов/полей на элемент; 1 миллион UTF-16 символов на текст, 8 миллионов суммарно. Проверки до больших управляемых аллокаций и текущий бюджет; превышение — `structure_too_large`, без обрезки или частичного результата. Сторонний провайдер без реализации инспектора явно возвращает недоступные секции.

## PostgreSQL

RepeatableRead/read-only транзакция, проверка существования/вида и права чтения объекта. Собственные PK/UNIQUE/FK/CHECK/exclusion и неизвестные native kinds, имена, порядок полей, FK mappings/actions/MATCH, deferrability/initially deferred/validated сохраняются. NOT NULL отражён в полях; отдельные native NOT NULL constraints видны, если сервер хранит их в pg_constraint.

Индексы сохраняют native definition, метод, unique/primary/partial/valid/ready, выражения и ключевые/INCLUDE термы. Неизвестный вид/неподтверждённое сопоставление снижает полноту. Для view/materialized view — pg_get_viewdef; полный CREATE TABLE не реконструируется, отсутствие раскрыто. Успешное чтение не инвалидирует текущие handles; запись по-прежнему независимо проверяет права/схему/исходную строку.

## SQLite

Обычные main-таблицы/представления, без миграции/checkpoint/записи; virtual/shadow остаются ограниченными. PK/UNIQUE и исходящие FK получены из PRAGMA. sqlite_autoindex не выдаётся за имя ограничения. Неявный целевой PK сохраняет неизвестные имена колонок как null. Термы различают столбцы, выражения (cid=-2), row identifier (cid=-1), ключевые/вспомогательные элементы.

Структурированные секции **частичные**: имена constraints, CHECK, deferrability и отдельный текст expression-термов не восстанавливаются парсером. Исходные CREATE TABLE/INDEX/VIEW сохранены целиком; method/validity/readiness остаются неизвестными. У view секции собственных табличных ограничений/индексов явно недоступны. UTF-8/UTF-16 raw metadata декодируется строго; повреждённый текст отклоняется без замены символов. Файловые SHA до/после чтения совпадают.
