# План работы SmartSQL

## Цель

Универсальный desktop-клиент для разных СУБД в направлении DBeaver: подключения, навигация по схемам и таблицам, просмотр и редактирование данных, поиск, обмен и перенос. Понятный интерфейс и безопасные действия сохраняются. Педагогическая практика остаётся проверочным сценарием диплома; ядро универсальное.

## Готовая основа

- Основной проект: `D:\Code\SmartSQL`. Экспериментальная модель: `D:\Code\SmartSQL-model`.
- Данные, копии, кэш, временные файлы и результаты тестов работают на D:; локальные артефакты исключены из Git. Прежние локальные файлы на C: сохранены как восстановительные копии.
- Локальный SQLite-редактор: типы полей, CRUD, поиск, сортировка, сохранённые фильтры, безопасные изменения структуры и восстановление.
- CSV/JSON/XLSX, сопоставление столбцов и предварительный просмотр; массовая вставка из Excel с проверкой и атомарным добавлением.
- Проверенная исходная точка: Release без предупреждений, 189 тестов приложения и 9 тестов модели.
- Коммиты: `fd98e1e` — прежний CSV/JSON этап; `b46562b` — пути D:, XLSX и вставка; `98c73fa` — отдельный репозиторий модели.

## Подключения и PostgreSQL: завершённая основа просмотра

Реализованы профили, PostgreSQL-провайдер, поиск/текстовая сортировка и desktop-обозреватель. Оболочка получила общую светлую тему, простой и расширенный режимы, правый инспектор структуры и русские ресурсы. Сборка проходит без предупреждений, 244 теста приложения проходят, включая восемь интеграционных проверок на отдельном PostgreSQL. Следующий этап — безопасное редактирование внешних таблиц по подтверждённым ключам.

1. **Общие контракты просмотра существующих БД.** Схемы, таблицы/представления, исходные типы столбцов, nullable, первичные ключи, страницы записей и сообщения об ограничениях. SQL остаётся в Infrastructure.
2. **Профили подключений.** Название, провайдер, адрес, порт, база, пользователь, режим TLS. Пароль вводится для текущего подключения и не сохраняется в JSON, Git или журнале.
3. **PostgreSQL: первая работающая вертикаль.** Подключиться к обычной существующей базе без метаданных SmartSQL; показать доступные объекты и структуру; читать страницы по 100 строк. Тайм-аут, отмена, корректное закрытие и понятные ошибки. Начать с просмотра без изменений.
4. **Desktop-окно подключений и просмотра.** Выбор профиля и таблицы, вкладки данных/структуры, пагинация и явные ограничения. Нативные типы PostgreSQL показываются без принудительного преобразования в четыре типа локального редактора.
5. **Проверка на отдельном PostgreSQL.** Использовать установленный runtime и отдельный временный кластер на D:; не менять существующий сервис или пользовательские базы. Проверить каталог, составной ключ, кавычки в именах, числовую точность, null, ограничения доступа, отмену и отсутствие мутаций.

Распределение работы сохраняет отдельного ответственного за каждый файл. Основной агент ведёт интеграцию, план/решения, окружение D:, общую сборку и Git.

Критерий завершения: пользователь открывает профиль PostgreSQL, видит реальные схемы/таблицы, структуру и страницы данных; пароль не остаётся на диске; данные БД не меняются; сборка и проверки проходят; результат закоммичен.

## Завершённый этап: безопасное изменение ячейки PostgreSQL

1. **Контракты и значения.** Необязательный `IDatabaseEditor`, подтверждённые возможности столбцов, явный NULL, сохранение пустых строк/пробелов и точности чисел. Ядро не содержит SQL.
2. **Провайдер.** Явное разрешение записи на текущую сессию, полный первичный ключ, временные разрешения строк, повторная проверка структуры/прав и сравнение исходной версии перед транзакционным изменением одной ячейки.
3. **Интерфейс.** Выбор строки и столбца, исходное/новое значение, нативный тип, причины запрета и проверка до сохранения. Конфликт предлагает обновление без автоматического повтора; неизвестный результат COMMIT показывается отдельно.
4. **Проверки.** Отдельная схема синтетических таблиц в тестовом PostgreSQL на D:. Проверить права, кавычки, составные ключи, NULL/пустоту, большие числа, отказ от округления, конкурентные изменения и ограничения нативных объектов.
5. **Интеграция.** Общая Debug-сборка и тесты через скрипты, проверка изменений и коммит исходников. Управление открытым приложением не требуется.

Параллельные направления: PostgreSQL-провайдер; интеграционные тесты и фикстуры; desktop-диалоги и состояния. Добавление/удаление внешних строк и общая отмена записей остаются отдельными следующими шагами.

Проверено 14 октября 2026: общая Debug-сборка без предупреждений; 330 тестов проходят (Domain 1, Application 103, Infrastructure 226), включая 20 PostgreSQL-проверок без пропусков. Подтверждены сохранение нативных типов, откат переполнения/округления, блокировка опасных выражений и отмена записи во время реального ожидания блокировки. Новые окна проверены сборкой и ревью кода; ручная проверка нового сценария интерфейса пока не проводилась.

## Следующие этапы

1. **Расширение безопасных операций внешних таблиц.** После изменения одной ячейки — добавление/удаление строк и более удобная работа с поддерживаемыми типами, с явным подтверждением и ограничениями. Объекты без подходящего ключа остаются доступными для просмотра.
2. **Полноценная работа с несколькими подключениями.** Быстрое переключение/вкладки, общий поиск и фильтры, экспорт и импорт с отчётом о совместимости.
   Для расширенного режима — ручной SQL-редактор с отменой, ограничениями, историей и сохранёнными запросами. Начать с выполнения запросов в режиме чтения; обычные внешние SQLite-базы также должны открываться через общий обозреватель.
3. **MySQL/MariaDB, затем SQL Server.** Подключать через те же контракты; показывать различия возможностей.
4. **Модель и переносимость.** Связи, ограничения, безопасное изменение типов, перенос проектов и миграция между провайдерами без скрытых потерь.
5. **Action/Permission и ИИ.** Сначала проверяемые действия, разрешения и аудит; затем подключение локальной модели. ИИ не получает произвольное выполнение SQL.
6. **Диплом и поставка.** Сквозной сценарий педагогической практики, документация, демонстрация, сборки под целевые ОС и инструкции установки/восстановления.

## Позже: резервные копии вне компьютера

Добавить облачные диски и личные серверы как дополнительные места хранения копий. Начать с базовых настроек: тип назначения, путь/адрес, профиль доступа, расписание, срок хранения и число версий. Поддержать локальную папку облачного клиента и сетевое хранилище; прямые протоколы/облачные API добавлять по конкретной потребности.

Сначала создаётся и проверяется локальная согласованная копия, затем отправляется на выбранное хранилище с проверкой целостности. Отдельно предусмотреть восстановление, журнал результата и понятные ошибки недоступности. Секреты доступа и сами копии остаются вне Git; настройки безопасности, шифрования и доступа выбираются явно. Реализация отложена до стабилизации работы с внешними СУБД.

После каждого значимого шага: сборка и необходимые тесты через скрипты D:, проверка изменений, обновление решений при необходимости, коммит только исходников. План уточняется по результатам проверок; календарные сроки пока не назначены.

Оформление развивается вместе с функциями: общие стили, словари и панели позволяют добавлять команды по назначению. Сначала завершаются русские сценарии, затем полная английская локализация. Правила расширения описаны в [интерфейсе](DESKTOP_INTERFACE.md).
