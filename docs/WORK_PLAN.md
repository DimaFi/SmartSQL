# План работы SmartSQL

## Цель

Универсальный desktop-клиент для разных СУБД в направлении DBeaver: подключения, навигация по схемам и таблицам, просмотр и редактирование данных, поиск, обмен и перенос. Понятный интерфейс и безопасные действия сохраняются. Педагогическая практика остаётся проверочным сценарием диплома; ядро универсальное.

## Готовая основа

- Основной проект: `D:\Code\SmartSQL`. Экспериментальная модель: `D:\Code\SmartSQL-model`.
- Данные, копии, кэш, временные файлы и результаты тестов работают на D:; локальные артефакты исключены из Git. Прежние локальные файлы на C: сохранены как восстановительные копии.
- Локальный SQLite-редактор: типы полей, CRUD, поиск, сортировка, сохранённые фильтры, безопасные изменения структуры и восстановление.
- CSV/JSON/XLSX, сопоставление столбцов и предварительный просмотр; массовая вставка из Excel с проверкой и атомарным добавлением.
- Проверенная исходная точка: Release без предупреждений, 189 тестов приложения и 9 тестов модели.
- Коммиты: `fd98e1e` — прежний CSV/JSON этап; `b46562b` — пути D:, XLSX и вставка; `98c73fa` — отдельный репозиторий модели.

## Текущий этап: подключения и PostgreSQL

Реализованы профили, PostgreSQL-провайдер и desktop-обозреватель. Сборка проходит без предупреждений, 240 тестов приложения проходят, включая шесть интеграционных проверок на отдельном PostgreSQL. Следующий этап — безопасное редактирование внешних таблиц по подтверждённым ключам.

1. **Общие контракты просмотра существующих БД.** Схемы, таблицы/представления, исходные типы столбцов, nullable, первичные ключи, страницы записей и сообщения об ограничениях. SQL остаётся в Infrastructure.
2. **Профили подключений.** Название, провайдер, адрес, порт, база, пользователь, режим TLS. Пароль вводится для текущего подключения и не сохраняется в JSON, Git или журнале.
3. **PostgreSQL: первая работающая вертикаль.** Подключиться к обычной существующей базе без метаданных SmartSQL; показать доступные объекты и структуру; читать страницы по 100 строк. Тайм-аут, отмена, корректное закрытие и понятные ошибки. Начать с просмотра без изменений.
4. **Desktop-окно подключений и просмотра.** Выбор профиля и таблицы, вкладки данных/структуры, пагинация и явные ограничения. Нативные типы PostgreSQL показываются без принудительного преобразования в четыре типа локального редактора.
5. **Проверка на отдельном PostgreSQL.** Использовать установленный runtime и отдельный временный кластер на D:; не менять существующий сервис или пользовательские базы. Проверить каталог, составной ключ, кавычки в именах, числовую точность, null, ограничения доступа, отмену и отсутствие мутаций.

Распределение: один субагент — контракты и профили; второй — PostgreSQL и проверки; третий — desktop-окна. Основной агент ведёт интеграцию, план/решения, окружение D:, общую сборку и Git. Общие файлы редактирует один ответственный.

Критерий завершения: пользователь открывает профиль PostgreSQL, видит реальные схемы/таблицы, структуру и страницы данных; пароль не остаётся на диске; данные БД не меняются; сборка и проверки проходят; результат закоммичен.

## Следующие этапы

1. **Безопасное редактирование внешних таблиц.** Надёжная идентификация строк по ключам, поддерживаемые типы, параметризованные изменения, транзакции и обнаружение конфликтов. Объекты без подходящего ключа остаются доступными для просмотра.
2. **Полноценная работа с несколькими подключениями.** Быстрое переключение/вкладки, общий поиск и фильтры, экспорт и импорт с отчётом о совместимости.
3. **MySQL/MariaDB, затем SQL Server.** Подключать через те же контракты; показывать различия возможностей.
4. **Модель и переносимость.** Связи, ограничения, безопасное изменение типов, перенос проектов и миграция между провайдерами без скрытых потерь.
5. **Action/Permission и ИИ.** Сначала проверяемые действия, разрешения и аудит; затем подключение локальной модели. ИИ не получает произвольное выполнение SQL.
6. **Диплом и поставка.** Сквозной сценарий педагогической практики, документация, демонстрация, сборки под целевые ОС и инструкции установки/восстановления.

После каждого значимого шага: сборка и необходимые тесты через скрипты D:, проверка изменений, обновление решений при необходимости, коммит только исходников. План уточняется по результатам проверок; календарные сроки пока не назначены.
