# UX Foundation — первый навигационный срез (UF09-01/02)

**Статус: source implementation candidate, not accepted.** Ветка `feat/ux-workspace-empty-actions-20261018`. Main/стабильное хранилище и provider SQL не изменяются, пока код находится в PR.

## Изменения

- В уже существующем `WorkspaceWindow` заголовок левой области теперь **«ИСТОЧНИКИ ДАННЫХ»**, а не «ПОДКЛЮЧЕНИЯ», поскольку там также находятся локальные проекты.
- Первичные действия названы по пользовательской цели: **«Создать проект…»**, **«Открыть проект…»**, **«Открыть SQLite-файл…»**, **«Подключить PostgreSQL…»**.
- Подпись каждого источника сообщает **тип**: локальный SmartSQL-проект, внешний SQLite-файл или PostgreSQL-сервер; строка статуса допуска различает обычное чтение и *ограниченные провайдером операции изменения*. Режим Simple/Advanced не меняет права СУБД.
- Если **вообще не осталось открытых вкладок**, центральная часть предлагает создание/открытие/подключение существующими обработчиками. Никакого нового создания файла этим экраном не происходит, пока пользователь не нажмёт действие. Подсказка объясняет необходимость сервера для PostgreSQL.
- Добавлен небольшой `WorkspaceSourceLabels` и тесты различения источников/режима доступа.

**Важно:** текущий `WorkspaceWindow` по-прежнему вызывает `OpenManagedView(new MainWindow())` в конструкторе, поэтому стартовый путь M03 *ещё не переделан*; новый пустой экран появляется лишь когда открытые вкладки отсутствуют. Убрать автоматический default project / построить Welcome первого запуска можно **отдельным** M03 срезом после проверки storage/onboarding контрактов. Не выдавать работу за полное исправление UF09-01/02.

## Acceptance (всё открыто)

1. Синтетические managed project, внешняя ordinary SQLite и PostgreSQL подключение: правильные подписи/значения без путаницы проекта и базы; один и тот же display name в двух источниках различим по endpoint.
2. Закрыть все вкладки без отключения источников: пустая панель показывается; каждое действие вызывает действующий диалог, cancel не создаёт БД, источник остаётся неизменённым.
3. Проверить создание и открытие существующего managed проекта и SQLite без скрытого managed metadata; PostgreSQL offline выводит понятную ошибку, не пустой проект.
4. Режим Simple/Advanced и Light/Gray, клавиатура, 100/150/200% DPI, минимальный размер, длинные русские подписи, screen reader.
5. Сохранение путей, активных сессий и закрытие вкладок без memory/resource leaks, regressions vs M02.
6. Запуск `scripts/Build.ps1`, `scripts/Test.ps1` на D:, документирование точной версии/среды, manual acceptance только после реального UI.

В среде создания этого PR Windows/D:/.NET SDK недоступны; исходники опубликованы, но код/автотесты/реальная UI-приёмка здесь **не выполнялись**.

После проверок: начать M03 Welcome/recents, не создавать новые базы автоматически; расширить управление пространством, источник/endpoint badges и системные сценарии отказов отдельными PR.
