# SmartSQL Personal — самостоятельная настольная редакция

**План продукта и реализации, 18 октября 2026.** Статус: proposal / docs only. Этот каталог — долговременное **расширение охвата** существующего SmartSQL, а не вторая очередь задач или утверждение о готовности функций.

## 1. Видение

Развить SmartSQL от действующего локального клиента к независимому персональному SQL/data-workbench с функциональным охватом, сопоставимым с **DBeaver Lite 26.2**. Сперва закончить личную настольную редакцию, потом отдельно спроектировать SmartSQL Team. Приоритет: **понятность, визуальная красота и безопасность работы с существующими базами**, а не воспроизведение чужого кода или пиксельная копия UI.

Рабочее имя: **SmartSQL Personal**; постоянное название продукта — SmartSQL. Не использовать в продукте DBeaver/Lite/Team как торговое имя. DBeaver — исключительно внешняя функциональная контрольная база.

Два равноправных пути в одной программе:
- **Simple / Excel-first:** открыть книгу/таблицу или существующую БД, понять источник и расположение данных, фильтровать, менять разрешённые ячейки, экспортировать и безопасно восстанавливать. SQL необязателен.
- **Advanced / SQL-first:** каталог объектов, SQL IDE, транзакции, планы запросов, анализ и визуальный конструктор. Это **уровень раскрытия инструментов**, а не смена прав или другой движок.

Одиночная работа не требует SmartSQL-сервера, регистрации, облака, ИИ либо новой СУБД. PostgreSQL и иные серверные движки выполняют свои операции сами; SmartSQL не разрабатывает СУБД, движок транзакций или синхронизируемую через облачную папку совместную SQLite-базу.

## 4. Приоритеты личной редакции

**P0 — качественная базовая программа.** Принять M01.04, исправить UF09-01…06, завершить M01.05/M01.06 после gate, M02/T23 и M03. Пользователь всегда понимает: какой источник открыт, где файл/сервер, что разрешено, что изменено и как вернуться назад.

**P1 — каждодневная ценность.** Мастер Excel→локальная БД, полные (без потерь типов) таблицы, нативный обмен, безопасные профили, хороший SQL-редактор и читабельные диагностические сообщения. Использовать принятые M04–M09/M10.

**P2 — профессиональная персональная редакция.** Дополнительные драйверы M14/M15; полные capabilities, ERD, конструктор SELECT, аналитические графики, подсказки SQL, корректный transaction workflow, план выполнения, расширенные просмотры значений и metadata. Каждый провайдер отдельно подтверждает покрытие.

**P3 — персональная автоматизация и ИИ.** Профили запросов, расписания локальных задач и безопасный локальный помощник после M17 Action/Permission; интеграции и SSO только с доказанным use case/доступом к тестовой инфраструктуре.

**После Personal — Team:** идентичности, сервер, общие ресурсы, RBAC, аудит, веб, эксплуатация. Не вводить заранее серверную зависимость в Personal.

## 5. Что значит «сопоставимый функционал»

Каждая функция проверяется по **пользовательскому исходу** и набору движков, а не наличию похожей кнопки. Для метки «паритет Lite» требуется матрица **возможность × СУБД × версия × ОС × режим доступа** + пройденные сценарии. Невозможно честно гарантировать 1:1 поддержку всех JDBC/ODBC-коннекторов и vendor-specific возможностей посредством общей абстракции .NET; «поддерживается» означает конкретно проверенный драйвер и subset, «частично» — явные ограничения. Team/Enterprise-only функции не объявлять частью Lite.

**Успех Personal:** пользователь Excel выполняет 5 основных действий без SQL и помощи; опытный SQL-пользователь выполняет SQL/metadata/data-workflows; данные сохраняются при сбоях; кроссплатформенность и доступность подтверждены. UI аккуратный на 100/150/200% масштабе, клавиатура, Narrator/аналог, светлая/серая темы, без скрытой потери данных.

## 6. Правила изменения этого пакета

Добавление функции: (1) привести официальный источник или собственный пользовательский сценарий, (2) указать статус в FEATURE_MATRIX, (3) найти существующий контракт/код и этап WORK_PLAN, (4) описать ошибки, безопасность, восстановление и acceptance, (5) реализовать отдельным PR, (6) обновить CAPABILITY_MATRIX/HANDOFF/WORK_PLAN только по доказанному факту. Никакой разработки «под список» без выполненных зависимостей. Принятые D001–D058 не менять без отдельного ADR в DECISIONS.

**Не хранить в репозитории:** реальные БД/профили с паролями, SQL-историю пользователя, runtime data, модели, payload сборки; все dev-артефакты SmartSQL по существующей D:-политике, пользовательские release-пути — по D056.

_Этот пакет создан как документация и не меняет runtime, product storage или очередность M01–M18._
