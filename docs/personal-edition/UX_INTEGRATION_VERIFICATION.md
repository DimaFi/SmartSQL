# UX Foundation — независимая сборка пяти PR

**Дата:** 19 октября 2026. **Текущее состояние:** инструмент проверки и ручной GitHub Actions workflow подготовлены; до реального выполнения это **не** evidence `passed`. Изменения приложения остаются в PR #30–34, `main` не содержит их автоматически.

## Почему мы делаем это до следующих функций

Накоплены 5 малых кодовых PR, проверенных по содержимому и границам, но ещё не собранных в одном проверенном приложении. Отдельное объединение **внутри одноразового worktree** позволяет обнаружить compile errors, collisions, тестовые регрессии, прежде чем хоть один PR менять `main`.

- PR #30 — создание таблицы: порядок полей и кнопки возле полосы прокрутки.
- PR #31 — локальный поиск внутри SQL-редактора (не выполняет запрос).
- PR #32 — локальные managed Boolean-значения (Да/Нет/NULL).
- PR #33 — названия источников/пустое рабочее пространство.
- PR #34 — native Boolean в диалоге с provider guard.

Рабочие файлы PR **не пересекаются** по состоянию на 19 октября. Новые commits надо снова сверять перед запуском. Отдельные «mergeable» статусы GitHub не гарантируют build или корректное объединённое поведение.

## Режим A: локальная синтетическая проверка уже выбранной ветки

На Windows в **D:\Code\SmartSQL**:

```powershell
git status --short
.\scripts\Verify-UxFoundation.ps1
```

Использует существующие `scripts/Build.ps1` и `scripts/Test.ps1` (не обходит D: правила и не изменяет установленный SDK). Сборка полная, тесты фильтруются по 5 новым классам.

## Режим B: все 5 PR вместе, не меняя checkout/main

```powershell
.\scripts\Verify-UxFoundation.ps1 -Combined
```

Скрипт создаёт уникальный **D:-worktree** внутри `.workspace/ux-foundation/verify-<guid>` (игнорируется Git), последовательно выполняет `git fetch origin refs/pull/{30..34}/head` и `git merge` **только в нём**. Затем строит полное решение и запускает тесты на этой объединённой версии. При конфликте/ошибке сохраняет worktree для разбора и выдаёт точный путь. Ничего не пушит, не принимает PR, не удаляет чужие файлы и не изменяет `main`.

```powershell
# Только если нужна полная проверка и доступны fixtures, включая разрешённый
# PostgreSQL, на которого реально нацелены integration tests.
.\scripts\Verify-UxFoundation.ps1 -Combined -FullTests
```

*Важно:* полный suite потребует существующих PG-fixtures/окружения, заданных в AGENTS/HANDOFF. Не инициализировать и не чистить чужой PostgreSQL. Текущий script не поднимает fixture сам и не считает её существующей.

## Режим C: явный GitHub Actions запуск (без локальной D: машины)

После того как **проверочный workflow** будет объединён в `main`:

1. Открыть GitHub → **Actions** → **SmartSQL UX Foundation (manual)**.
2. Нажать **Run workflow** в ветке `main`.
3. Windows runner установит .NET 10, проверит путь D:, создаст отдельный рабочий каталог, сведёт пять PR и запустит сборку и пять тестовых классов.
4. Смотреть реальный результат в логах workflow run, а не считать факт наличия YAML успехом. При падении не объединять PR #30–34, исправить причины в отдельной ветке и повторить.
5. GitHub Actions запуск может использовать доступные минуты аккаунта/организации. Нет push/pull_request расписания — **только ручной выбор пользователя**.

Настроены `permissions: contents: read`, без доступа к cloud credentials / secrets, и ограничение выполнения 45 минут. Не прикреплять реальные пользовательские базы, пароли или user SQL. GitHub runner не заменяет работу на чистом пользовательском Windows без D: и manual GUI.

## Приёмка после зелёного CI

```text
[ ] Полный build на объединённом исходнике (точные SHAs PR)
[ ] xUnit: test count/pass/fail/skip, actual logs/TRX, no invented claims
[ ] Windows mouse/keyboard: UF09-03,04,05,01/02, SQL-find Ctrl+F/F3
[ ] Light/Gray, 100/150/200% DPI, minimum window and screen reader
[ ] Реальные synthetic managed SQLite reopen/NULL/undo
[ ] Нативные SQLite/PG права, fail/conflict/unknown COMMIT без повторов
[ ] Проверено, что main/remote не поменялись от пробного прогона
[ ] Каждому PR присвоен верный final scope; merge индивидуально после review
[ ] Обновлены CAPABILITY_MATRIX/HANDOFF/USER_FEEDBACK/WORK_PLAN только по доказательствам
```

**Отсутствие ручного UI или PG-проверок оставляет соответствующие gates открытыми**, даже если автоматическая сборка успешна.
