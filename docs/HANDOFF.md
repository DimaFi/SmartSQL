# Продолжение SmartSQL в новом чате

Прочитайте `AGENTS.md`, затем [WORK_PLAN.md](WORK_PLAN.md), [TASKS.md](TASKS.md), [CAPABILITY_MATRIX.md](CAPABILITY_MATRIX.md), [DECISIONS.md](DECISIONS.md). Проверьте `git status` и последние коммиты: рабочее дерево может содержать более новый незавершённый срез.

## Приоритеты и ограничения

- Ближайшая цель — удобный PostgreSQL/SQLite, затем SQL/обмен, английский и остальные СУБД. Оба режима важны; первый запуск — выбор, далее запоминание и постоянная кнопка переключения.
- Целевой UI: одно главное окно, дерево подключений слева, вкладки по центру, сворачиваемый инспектор справа. Это принятая цель D038, а не уже готовая оболочка.
- Рабочая папка `D:\Code\SmartSQL`; модель отдельно `D:\Code\SmartSQL-model`. Данные/копии/кэш/временные файлы/результаты/веса остаются на D: и игнорируются Git. Установленные инструменты и глобальные настройки не переносить/не менять.
- Пользователь запретил управление ПК. Разрешены скриншоты для понимания; нельзя автоматически управлять окнами/мышью/клавиатурой или запускать/закрывать приложение. Файлы, CLI-сборки и тесты разрешены.
- Субагенты: `gpt-6.1-sol` medium или `gpt-5.6-sol` high; без Astra/extra-high. Отдельные владельцы файлов; интеграция, проверки и Git — в основном агенте.
- Дедлайна нет. Облачные диски/личные серверы для копий — позже. Встроенный ИИ и серверный режим до устойчивого desktop не добавлять.

## Проверенная основа и активная работа

Предыдущий закоммиченный функциональный этап — `f57751c`: безопасное изменение одной ячейки PostgreSQL. Проверка: 330 тестов (Domain 1, Application 103, Infrastructure 226), включая 20 PostgreSQL-фактов без пропусков; Debug без предупреждений. Это предыдущий результат, не результат текущего незавершённого этапа. `a955126` сохраняет согласованный план.

Текущий цикл T01–T03 реализован и проверен в локальном коммите `fa36f26`: PostgreSQL INSERT, обычный SQLite для чтения, форма новой строки и общий обозреватель. Debug без предупреждений; 355 тестов (Domain 1, Application 108, Infrastructure 246), включая 30 PostgreSQL-фактов, без пропусков. Подтверждены отмена и защитная блокировка против конкурентного index DDL. Новые UI-сценарии требуют ручной приёмки T04; общий интерфейс со вкладками ещё не реализован.

Следующий проверенный срез T06 реализует удаление одной PostgreSQL-строки: отдельные SELECT/DELETE-возможности без обязательного UPDATE, приватный одноразовый DeleteHandle, guard структуры/прав/связей, сравнение PK/xmin/исходных значений, ровно одна строка или откат. Все входящие FK пока запрещены (включая RESTRICT/NO ACTION и самоссылку); исходящие допускают удаление дочерней строки. Добавлен отдельный русский диалог подтверждения; успешное удаление и последующая ошибка/отмена обновления страницы разделены. Debug без предупреждений, 374 теста (1/113/260), 41 реальная PostgreSQL-проверка, без пропусков. Реальный ADD FK ждёт защитную блокировку; отмена обоих действий не оставляет FK/удаления. Неизвестный COMMIT проверен ревью, без сетевой fault injection. Ручная UI-приёмка T04 остаётся открытой. Коммит среза ищите в `git log` по сообщению `Add confirmed PostgreSQL row deletion and prepare GitHub tasks`.

Локальный SQLite-проект SmartSQL и обычная SQLite-база — разные процессы. Не мигрировать чужой файл в SmartSQL молча. Нативный PostgreSQL не сводить к четырём локальным типам; внешний обмен пока отдельно запланирован.

## Проверки

```powershell
./scripts/Build.ps1 -Configuration Debug -NoRestore
./scripts/Test.ps1 -Configuration Debug -NoBuild -NoRestore
```

Для PostgreSQL-фактов используется только отдельный кластер `D:\Code\SmartSQL\.workspace\postgresql-tests`, loopback `127.0.0.1:15432`, база `smartsql_browser_test`, роли `smartsql_test_admin`, `smartsql_browser_reader`, `smartsql_browser_editor`. Runtime находится в `C:\Program Files\PostgreSQL\17\bin`, фактически 17.2; он остаётся на месте. Существующий сервис `postgresql-x64-17` и пользовательские базы не менять.

После проверки абсолютного пути тестовый кластер можно запустить/остановить через `pg_ctl`. Фикстуры уже подготовлены: не повторять `initdb`, создание базы или `PostgresBrowser.sql`. Для полного прогона задать на время процесса `SMARTSQL_POSTGRES_TEST_PORT=15432`; без него PostgreSQL-факты явно пропускаются. Все артефакты находятся в `.workspace` на D:.

Собирать Debug: пользовательское Release-приложение может быть открыто. Не закрывать его и не менять Release-файлы ради сборки.

## GitHub и публикация

Назначение `origin`: `https://github.com/DimaFi/SmartSQL.git`. Пользователь явно попросил публиковать планы/задачи/коммиты в GitHub для продолжения в другом чате.

14 октября повторная проверка: GitHub-коннектор читает `DimaFi/SmartSQL`, но создание Issue и запись `docs/WORK_PLAN.md` возвращают `403 Resource not accessible by integration`. Установка DimaFi `90365160` настроена на Selected repositories; SmartSQL отсутствует в выданном списке. Пользователю отправлена точная инструкция добавить SmartSQL через `https://github.com/settings/installations/90365160`. Репозиторий пустой, Issues отсутствуют; ничего не опубликовано. Подготовлено 26 записей (общий план + T01–T25) в [github-issues.json](github-issues.json). Перед повторной публикацией проверить доступ и существующие задачи, чтобы не создавать дубликаты.

Git CLI по-прежнему без рабочей авторизации: с явным аккаунтом DimaFi не получил пароль/токен (`terminal prompts disabled`). Доступ коннектора и авторизация Git — разные проверки. Токены/пароли не запрашивать в сообщениях и не сохранять в проекте. Статус T05 остаётся открытым до подтверждения URL задач и удалённого коммита; подготовленные файлы не означают публикацию.

После восстановления доступа проверить удалённые ветки и совместимость истории, опубликовать обычным push без force, затем сравнить удалённый SHA с локальным. Не сообщать «опубликовано», пока это не подтверждено. GitHub Issues можно связать с T-ID, сохраняя критерии и зависимости; обновлять существующие задачи вместо дубликатов.
