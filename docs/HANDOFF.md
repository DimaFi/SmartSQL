# Продолжение SmartSQL в новом чате

Прочитайте `AGENTS.md`, затем [WORK_PLAN.md](WORK_PLAN.md), [TASKS.md](TASKS.md), [CAPABILITY_MATRIX.md](CAPABILITY_MATRIX.md), [DECISIONS.md](DECISIONS.md). Проверьте `git status` и последние коммиты: рабочее дерево может содержать более новый незавершённый срез.

## Приоритеты и ограничения

- Ближайшая цель — удобный PostgreSQL/SQLite, затем SQL/обмен, английский и остальные СУБД. Оба режима важны; первый запуск — выбор, далее запоминание и постоянная кнопка переключения.
- UI реализован вокруг одного `WorkspaceWindow`; [приёмка](WORKSPACE_UI_ACCEPTANCE.md) частичная, оставшиеся сценарии открыты.
- Рабочая папка `D:\Code\SmartSQL`; всё для ML строго внутри `D:\Code\SmartSQL-model`, будущий репозиторий `https://github.com/DimaFi/SmartSQL-ML`. В модели отдельные scripts/config и кэши; source/tests/cases сохраняют имена. Данные/копии/кэш/временные файлы/результаты/веса игнорируются Git. Установленные инструменты и глобальные настройки не переносить/не менять.
- 15 октября пользователь явно разрешил подключение к экрану и управление приложением для ограниченных тестов SmartSQL на синтетических данных в D:. Не использовать это разрешение для других приложений, пользовательских баз или несогласованных внешних действий.
- Субагенты: `gpt-6.1-sol` medium или `gpt-5.6-sol` high; без Astra/extra-high. Отдельные владельцы файлов; интеграция, проверки и Git — в основном агенте.
- Дедлайна нет. Облачные диски/личные серверы для копий — позже. Встроенный ИИ и серверный режим до устойчивого desktop не добавлять.

Текущий реализованный срез T07/T08 объединяет desktop в одном `WorkspaceWindow`. Слева находится одно дерево: управляемые SQLite-проекты, открытые PostgreSQL-подключения и открываемые обычные SQLite-файлы; сохранённые несекретные профили по-прежнему управляются в `ConnectionsDialog`. Управляемый редактор `MainWindow` встроен как содержимое вкладки с прежними CRUD/схемой/обменом, но без собственного дублирующего дерева. Нативные таблицы открываются в `DatabaseTableView`; каждая вкладка владеет независимой сессией провайдера, состоянием страницы и отменой. Стабильная уникальная идентичность класса подключения не смешивает одинаковые имена, а закрытие вкладки отменяет незавершённую загрузку. Вкладки и пароли не сохраняются.

Simple/Advanced выбирается при первом запуске через отдельный диалог, затем сохраняется атомарно в локальном JSON и переключается глобально. Переключение синхронизирует открытые представления, сохраняет их данные/состояние и не меняет права записи. Ручной SQL не добавлен. Исторические ориентиры, не текущая проверка: `f57751c` — 330 тестов (1/103/226, 20 PostgreSQL-фактов); `fa36f26` для T01–T03 — 355 (1/108/246, 30 фактов); срез T06 удаления PostgreSQL — 374 (1/113/260, 41 факт). T06 использует независимые SELECT/DELETE-возможности, одноразовый handle, проверку PK/xmin/исходных значений и защитную блокировку; все входящие FK по-прежнему запрещены. Неизвестный COMMIT проверен ревью без сетевой fault injection.

Локальный SQLite-проект SmartSQL и обычная SQLite-база — разные процессы. Не мигрировать чужой файл в SmartSQL молча. Нативный PostgreSQL не сводить к четырём локальным типам; внешний обмен пока отдельно запланирован.

После проверки абсолютного пути тестовый кластер можно запустить/остановить через `pg_ctl`. Фикстуры уже подготовлены: не повторять `initdb`, создание базы или `PostgresBrowser.sql`. Для полного прогона задать на время процесса `SMARTSQL_POSTGRES_TEST_PORT=15432`; без него PostgreSQL-факты явно пропускаются. Все артефакты находятся в `.workspace` на D:.

Собирать Debug: пользовательское Release-приложение может быть открыто. Не закрывать его и не менять Release-файлы ради сборки.
