# Фильтры и сортировка обычных баз

В нативной вкладке доступны поиск, **Фильтры: N**, выбор столбца сортировки и сброс всего запроса. До 20 условий объединяются **И** и выполняются вместе с поиском до LIMIT/OFFSET. Условия сохраняются при обновлении, переходе между страницами/вкладками и переключении режима. NULL задаётся отдельными операциями; пустой текст и пробелы остаются значениями. Значение ограничено 1024 символами, поиск — 256; SQL из ввода не исполняется.

Возможности подтверждает провайдер по текущей структуре и перепроверяет при выполнении. Старый провайдер без поддержки условий отказывает явно. Значения передаются параметрами; имена выбираются из метаданных и экранируются. Все выбранные сортировки нативные, NULL первыми в обоих направлениях; PK используется для дополнительного порядка, если доступен. Каждая страница всё ещё читает отдельный снимок, поэтому параллельные изменения могут сдвигать строки.

## PostgreSQL

Поддержаны подтверждённые встроенные `text/varchar`, `int2/int4/int8`, `numeric`, `date`, `bool`. Числа сравниваются по типу: 2 меньше 10. Numeric передаётся исходной десятичной строкой и не округляется через .NET decimal. Целые ограничены нативным диапазоном; даты — существующими YYYY-MM-DD в годах 0001–9999; Boolean — true/false. Текст сравнивается буквально и с учётом регистра в collation C; `%` и `_` не становятся шаблоном.

Сравнения/выбранная сортировка недоступны для domains и остальных неподдерживаемых типов; проверки NULL остаются доступны. Точное OID/namespace/имя/вид типа подтверждаются повторно под блокировкой отношения в read-only транзакции. Используются квалифицированные встроенные casts/операторы/функции. Права на изменение не требуются и не расширяются.

## SQLite

Типизированные сравнения поддержаны для объявленных текстовых, целых, числовых, DATE и BOOLEAN типов. Перед сравнением весь затронутый столбец, включая строки вне страницы и поиска, проверяется в том же снимке. Несовместимые классы хранения отклоняются явно; преобразования и молчаливого исключения строк нет.

- INTEGER — точный Int64; числовой ввод — точный Int64 либо конечный double с совпадающим обратимым десятичным представлением. Например, `0.10000000000000001` не округляется до `0.1` молча.
- TEXT — фактический TEXT с корректной исходной UTF-8/UTF-16 кодировкой; текстовые условия учитывают регистр и воспринимают знаки буквально.
- DATE — фактический TEXT с существующей датой строго `yyyy-MM-dd`.
- BOOLEAN — фактический INTEGER 0/1; ввод true/false или 0/1.
- Неизвестные объявления разрешают только NULL-условия. Нативная сортировка доступна по классам хранения SQLite (числа, затем текст, затем binary), с явной диагностикой. Это не сортировка строковых представлений.
