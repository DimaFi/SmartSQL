# Открытие и создание проекта SmartSQL — M01.01

Реализован отдельный срез безопасного выбора файла. Это не мастер первого запуска, не новая product storage policy и не полная приёмка совместимости M01.02.

## Контракт

- `SqliteWorkspace.OpenExisting(path)` требует существующий файл. До любого upgrade выполняется read-only проверка версии и ожидаемых служебных таблиц/столбцов/PK и необходимых unique indexes. Совпадение расширения или единственной таблицы `smartsql_tables` недостаточно. Пустой, посторонний, неполный формат и metadata triggers отвергаются с подсказкой «SQLite…». Неподдерживаемая версия и не-SQLite/повреждённые байты получают отдельный отказ. Открытие не создаёт отсутствующий файл или родительский каталог.
- `SqliteWorkspace.CreateNew(path)` отказывает для существующего файла/каталога и обнаруженных SQLite sidecars. Схема создаётся в уникальном соседнем временном файле без pooling; закрытый готовый файл публикуется `File.Move(..., overwrite:false)`. Конкурирующее создание имеет одного победителя. Ошибка не удаляет чужое назначение; очистка относится только к собственному временному имени.
- Неоднозначный публичный конструктор удалён. Рабочие соединения используют `ReadWrite`, поэтому исчезновение файла не создаёт новую пустую базу при следующей операции.
- Существующие совместимые legacy v0/v1/v2 сохраняют прежний upgrade и копию before-upgrade. Их схема проверяется повторно под writer transaction. Исторический v1 без поздних field FK/unique constraints не объявляется повреждённым только из-за этих отсутствующих ограничений. Текущая версия остаётся 3, новый частный маркер не добавляется.
- Restore проверяет свою временную копию через ту же managed-проверку. Исходная копия и активная база не подменяются пустым/ordinary источником.

## Desktop

«Открыть проект», повторное открытие таблицы, refresh, restore-reopen и demo-reopen используют OpenExisting. «Новый проект» явно вызывает CreateNew и передаёт уже созданное рабочее пространство в редактор. Старый встроенный toolbar обновлён аналогично. Для собственного default/demo пути сохранён существующий выбор: известный файл открыть, отсутствующий создать; конфликт или посторонний файл не превращается в новый проект. Удаление автоматического default creation относится к будущему M03.

Ошибка выбора нового проекта/открытия показывается в статусе общего окна; существующая вкладка не заменяется, если проверка файла отказала. Нативные права, Simple/Advanced, темы, read-only SQL и запись ordinary SQLite/PostgreSQL не расширены.
