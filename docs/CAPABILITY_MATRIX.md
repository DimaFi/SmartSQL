## Общее рабочее место

- Один `WorkspaceWindow` содержит общее дерево и центральные вкладки. Управляемый SQLite открывается во встроенном редакторе без второго дерева.
- Каждая нативная таблица использует отдельную сессию провайдера и собственное состояние страницы. Уникальная идентичность подключения разделяет одноимённые базы/таблицы; закрытие вкладки отменяет незавершённую загрузку.
- Simple/Advanced выбирается при первом запуске, сохраняется атомарно в локальном JSON и синхронизируется между открытыми представлениями. Режим представления не меняет разрешения записи.
- Открытые вкладки и учётные данные не сохраняются. SQL-вкладки обычных подключений независимы, запуск явный; локальная история хранит 30 успешных SQL, включая значения, без результатов и пароля профиля.

## Ограничения, которые нельзя скрывать

- SQLite-проект использует логические `Text`, `Number`, `Date`, `Boolean`; физические пользовательские столбцы хранятся как TEXT. Числа ограничены точностью .NET `decimal`; недопустимая точность отклоняется. Локальный ввод пустоты/одних пробелов нормализуется в NULL. Эти правила нельзя автоматически переносить на нативные БД. Обычный SQLite читается отдельно: INTEGER64, обратимое double-представление REAL, BLOB hex и исходная кодировка TEXT; у WAL возможны служебные sidecar-файлы.
- PostgreSQL сохраняет различие NULL, пустой строки и пробелов. Редактируются встроенные `text`, `varchar`, `int2`, `int4`, `int8`, `numeric`, `date`, `bool`. `uuid` допустим как ключ, но не как изменяемое поле. При UPDATE domain, неподдерживаемые типы, PK, unique-index, identity/generated поля защищены. При INSERT поддерживаемые PK/unique поля допускают явный ввод, identity/generated заполняются сервером; неподдерживаемое поле требует безопасного DEFAULT. Числовой ввод ограничен 1024 символами, даты — годами 0001–9999.
- Для PostgreSQL UPDATE нужны обычная несекционированная таблица, надёжный PK и SELECT/UPDATE. Для INSERT отдельно нужны SELECT/INSERT и право защитной блокировки (MAINTAIN на 17+ либо UPDATE/DELETE/TRUNCATE); sequence-права проверяются отдельно. Наследование, RLS, пользовательские триггеры, UPDATE-правила и небезопасные выражения ограничений, вычисляемых полей, индексов или вывода типов блокируют запись. Возможность чтения не означает возможность изменения.
- Для DELETE нужны SELECT/DELETE, без обязательного UPDATE. Удаление защищено отдельным одноразовым разрешением текущей страницы; после отправленной попытки, включая ошибку/отмену, требуется перечитать строку. Все входящие FK, включая самоссылки/RESTRICT/NO ACTION, и DELETE-правила запрещены. Исходящие FK сами по себе допускают удаление дочерней строки. Резервное копирование или общая отмена внешнего удаления не реализованы.
- Каждая PostgreSQL-страница читает отдельный снимок; параллельные изменения могут сдвигать строки между страницами. Разрешение на изменение строки действует только для текущей страницы до 15 минут. Это не переносимый идентификатор строки.
- Локальный экспорт охватывает всю таблицу независимо от фильтров. CSV для Excel меняет формулоподобный текст защитным апострофом; XLSX сообщает о потерях возможностей книги; `SmartSQL.Table.v1` не переносит весь проект, связи, ID записей и сохранённые фильтры. Новый нативный обмен должен отдельно определять формат, область выгрузки и согласованность чтения.
