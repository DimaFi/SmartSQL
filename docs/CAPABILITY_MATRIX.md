# Матрица возможностей SmartSQL

Состояние исходников на проверенной базе `f57751c`, 14 октября 2026. Общая Debug-сборка прошла без предупреждений; **330 тестов** (Domain 1, Application 103, Infrastructure 226), включая **20 реальных PostgreSQL-проверок**, прошли без пропусков. Это результат предыдущего этапа, а не новая проверка при подготовке плана. Подробности: [план работы](WORK_PLAN.md) и [PostgreSQL](POSTGRESQL_BROWSER.md).

«Реализовано» означает наличие кода и проверок в этой базе. Это не означает, что каждый пользовательский сценарий проверен вручную. Новый интерфейс изменения ячейки PostgreSQL проверен сборкой и ревью кода; **ручная проверка нового сценария пока не проводилась**. Для локального редактора сохранены предыдущие демонстрационные скриншоты; они не заменяют полную ручную проверку текущей версии.

## Три разных режима работы

| Возможность | SQLite-проект SmartSQL | Обычная существующая SQLite-база | Обычная существующая PostgreSQL-база |
| --- | --- | --- | --- |
| Открытие | Реализовано: создание/открытие проекта со служебными метаданными SmartSQL | Не реализовано; локальный редактор отклоняет чужую базу с пользовательскими таблицами | Реализовано: подключение без метаданных SmartSQL; профили без пароля, пароль только на сессию |
| Каталог и структура | Логические таблицы и четыре типа полей SmartSQL | Не реализовано | Нативные схемы, таблицы, представления, типы, nullable, порядок составного PK; полный инспектор FK/индексов/ограничений пока отсутствует |
| Чтение | Пагинация, поиск, сортировка | Не реализовано | Страницы по 100 в UI; полные текстовые представления сервера, явный отказ при превышении лимитов |
| Фильтры | Комбинированные условия AND, операции по типам полей, сохранённые пресеты | Не реализовано | Буквальный поиск по тексту всех столбцов; выбранная сортировка текстовая. Внешние фильтры по типам и пресеты не реализованы |
| Изменение ячейки | Реализовано для четырёх логических типов | Не реализовано | Реализовано при явном разрешении на сессию, подтверждённом PK и безопасной таблице/поле; структура и исходная строка проверяются повторно |
| Добавление/удаление строк | Реализовано; массовая вставка добавляет строки атомарно | Не реализовано | Не реализовано; контракт редактора сейчас содержит только изменение одной ячейки |
| Изменение структуры | Создание, переименование, добавление и безопасное удаление полей/таблиц | Не реализовано | Не реализовано; просмотр ограничений не даёт права менять структуру |
| Смена типа, связи | Не реализованы | Не реализованы | Не реализованы; существующие ограничения сервера продолжают действовать |
| CSV/JSON/XLSX и вставка Excel | Реализовано для управляемых таблиц, с проверкой, preview и сообщениями о несовместимости | Не реализовано | Не реализовано; перенос через четыре локальных типа без отчёта о потерях недопустим |
| Резервная копия/восстановление | Ручные и защитные копии файла, проверенное восстановление SmartSQL-проекта | Не реализованы в клиенте для этого режима | Не реализованы; локальная копия SQLite не является резервной копией PostgreSQL |
| Отмена записей | Отмена последнего изменения ячейки в локальном UI | Не реализована | Не реализована; конфликт и неизвестный COMMIT требуют обновления и проверки, автоматического повтора нет |
| Ручной SQL / ИИ | SQL-редактор отсутствует; «Запрос словами» — ограниченный детерминированный разбор фильтров | Не реализованы | SQL-редактор и ИИ не реализованы; будущий ИИ должен работать через Action/Permission |

MySQL/MariaDB и SQL Server **только запланированы**: провайдеров, подключений, просмотра и записи для них сейчас нет. Перенос между СУБД и единый полноценный рабочий процесс нескольких подключений также остаются будущими этапами.

## Ограничения, которые нельзя скрывать

- SQLite-проект использует логические `Text`, `Number`, `Date`, `Boolean`; физические пользовательские столбцы хранятся как TEXT. Числа ограничены точностью .NET `decimal`; недопустимая точность отклоняется. Локальный ввод пустоты/одних пробелов нормализуется в NULL. Эти правила нельзя автоматически переносить на нативные БД.
- PostgreSQL сохраняет различие NULL, пустой строки и пробелов. Редактируются встроенные `text`, `varchar`, `int2`, `int4`, `int8`, `numeric`, `date`, `bool`. `uuid` допустим как ключ, но не как изменяемое поле. Domain, неподдерживаемые типы, PK, unique-index, identity и generated поля остаются только для чтения. Числовой ввод ограничен 1024 символами, даты — годами 0001–9999.
- Для записи PostgreSQL нужны обычная несекционированная таблица, надёжный полный PK и права SELECT/UPDATE. Наследование, RLS, пользовательские триггеры, UPDATE-правила и небезопасные выражения ограничений, вычисляемых полей, индексов или вывода типов блокируют запись. Возможность чтения не означает возможность изменения.
- Каждая PostgreSQL-страница читает отдельный снимок; параллельные изменения могут сдвигать строки между страницами. Разрешение на изменение строки действует только для текущей страницы до 15 минут. Это не переносимый идентификатор строки.
- Локальный экспорт охватывает всю таблицу независимо от фильтров. CSV для Excel меняет формулоподобный текст защитным апострофом; XLSX сообщает о потерях возможностей книги; `SmartSQL.Table.v1` не переносит весь проект, связи, ID записей и сохранённые фильтры. Новый нативный обмен должен отдельно определять формат, область выгрузки и согласованность чтения.

## Зависимости будущих срезов

| Срез | Что требуется до реализации | Проверяемый результат |
| --- | --- | --- |
| Ручная проверка изменения PostgreSQL | Отдельная тестовая база | Проверены NULL/пустота, запреты, успешная запись, конфликт, отмена и повторное чтение; статус UI записан отдельно от автотестов |
| Удаление внешней строки | Отдельная возможность DELETE, PK/исходная версия, права, сведения о FK и каскадах; нельзя наследовать разрешение UPDATE | Подтверждение конкретной строки и известных последствий; ровно одна строка либо откат/конфликт; опасные каскады явно запрещены или полностью показаны |
| Добавление внешней строки | Отдельная возможность INSERT, required/default/identity/generated метаданные; различие «не задано», NULL и значения; проверка ограничений | Пользователь понимает, какие поля заполняет сервер; нативные данные не округляются, результат вставки возвращается, неизвестный COMMIT не повторяется автоматически |
| Фильтры по типам и нативная сортировка | Структурированные операции и подтверждённые возможности нативных типов; SQL остаётся в провайдере | Числа/даты сравниваются нативно; NULL задан явно; неподдерживаемая операция объясняется, без скрытой подмены текстовым сравнением |
| Просмотр обычного SQLite | Отдельный адаптер `IDatabaseBrowser`, без создания/миграции метаданных SmartSQL | Чужая база открывается для чтения; структура и ограничения показаны; исходный файл не меняется |
| Нативный обмен | Описание типов и совместимости, правила NULL/точности, scope и снимка выгрузки; сначала чтение/экспорт, затем preview импорта | Несовместимые типы/свойства обнаружены до записи; пропуски согласованы явно; импорт и экспорт имеют описанные границы обратимости |

Порядок, зависимости и критерии следующих этапов ведутся в [WORK_PLAN.md](WORK_PLAN.md); архитектурные изменения — в [DECISIONS.md](DECISIONS.md). Матрица фиксирует текущее состояние и зависимости; порядок исполнения и приёмка определены планом.
