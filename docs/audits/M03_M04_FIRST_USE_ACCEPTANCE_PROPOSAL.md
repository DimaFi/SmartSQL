## 1. Правило: открытие ≠ создание ≠ импорт ≠ копия

| Действие | Что делает пользователь | Что нельзя делать автоматически |
| --- | --- | --- |
| «Открыть существующую базу» | Выбор managed SmartSQL / обычного SQLite / подключение PostgreSQL | CreateNew на missing/empty/foreign; convert ordinary SQLite в managed; изменять схему |
| «Создать локальный проект» | Выбор нового пути; локальный SQLite уже встроен | Скрыто создавать default DB до выбора; перезаписывать имеющуюся |
| «Начать с Excel или CSV» | Выбор источника, листов, колонок, трансформаций, новой БД | Игнорировать второй лист, потерять leading zero, запускать макрос/формулу как код |
| «Восстановить из копии» | Выбор локальной/облачной проверенной копии; restore в новую цель | Считать эту кнопку действующей до M05; overwrite активной БД/ключ без согласия |
| «Подключить сервер PostgreSQL» | Адрес/порт, DB, учётная запись/права, TLS | Скачивать/устанавливать сервер без согласия; просить root/superuser права без нужды |

**Явный статус в M03 до M04/M05:** кнопку Excel→новый проект и cloud restore показывать как «Пока недоступно» или не показывать, если нет настоящего работающего сценария; не создавать фиктивные экраны с «успешно». Уже существующие CSV/XLSX обмен и локальные backup/restore должны оставаться доступны там, где реально поддерживаются.

## 2. Короткий welcome по аудиториям

### A. Пользователь уже имеет БД или другой GUI

**Первое действие:** «Открыть существующую базу».
Подпись: «SQLite открывается как файл. Для PostgreSQL нужен адрес работающего сервера. Другой редактор баз устанавливать не требуется».
Выбор: «SQLite-файл», «Проект SmartSQL», «PostgreSQL».
Статус: «Открыто для просмотра» / «Редактирование недоступно для этой таблицы» (по provider capabilities, а не Simple/Advanced).
Ошибки: «Файл не найден. Проверьте расположение или укажите другой файл»; «Это обычная база SQLite. Откройте её без преобразования»; «Не удалось подключиться к серверу. Проверьте адрес, сеть, права и TLS».
Успех: исходный файл SHA/metadata неизменён, native table открыта, просмотр не расширяет разрешение на запись, имя/путь видны.

### B. Специалист, у которого сервер пока не установлен

**Первое действие:** «Создать локальный проект».
Подпись: «Для локальной работы ничего дополнительно устанавливать не нужно: SQLite встроен в SmartSQL».
Параллельная опция: «Нужна общая база для команды? Подключите PostgreSQL», ссылка [официальная установка PostgreSQL](https://www.postgresql.org/download/).
Успех: явно выбранный новый путь, открытая таблица/пустой проект согласно текущему рабочему продукту, опция «Где файл?», нет незапрошенного server installer.
Ошибки: выбранный файл существует / путь недоступен / места недостаточно — не создавать альтернативный default. Не обещать «многопользовательский SQLite» через shared cloud folder.

### C. Новичок из Excel

**Вход:** «Начать с Excel или CSV».
Подпись: «SmartSQL покажет, как будут сохранены значения; исходная книга останется без изменений».
Порядок: файл → все листы и scope → заголовки/столбцы/тип по колонке → raw vs effective stored value → предупреждения о потерях → новое имя и путь проекта → явное подтверждение → результат/«Где проект?».
Кнопки мастера: «Назад», «Отменить», «Проверить данные», «Создать проект».
Успех: source SHA неизменён, каждая выбранная строка/колонка учтена, никакой неподтверждённой подмены типовой семантики, cancel/error = нет частичной пользовательской БД.
До реализации полного M04 это **не** реально существующий flow.

## 3. Обязательные случаи Excel: не выдавать красивый preview за сохранность

| Исходное значение | Что обязан показать preview | Условие подтверждения |
| --- | --- | --- |
| Ячейка отображается как 00123 | Реальное raw значение + форматирование Excel и proposed saved text; утраченные до чтения ведущие нули нельзя восстановить по предположению | Поле Text по умолчанию для кода/ID; предупредить, если библиотека уже вернула 123 |
| Длинное число/Scientific notation | Исходное содержимое, проверку decimal precision и сохранённый результат | No rounding silently; unavailable exactness = reject/explicit disclosure |
| Пустая строка, whitespace, реально отсутствующая ячейка | Разные исходные состояния и effective stored value | Текущий managed FieldValue нормализует пустоту/пробелы в NULL — нужна отдельная D/compat decision перед новым обещанием |
| Формула с cached value | Formula/cached value/source and chosen data-only scope | Не исполнять формулы/макросы/внешние ссылки; уточнить, что формула не переносится как вычисление |
| Дата/время и timezone | Excel serial/display interpretation + saved date text / потерянные часы/zone | Нельзя автоматически выкинуть время и написать «без потерь» |
| Несколько листов, hidden/blank/duplicate headings | Полный перечень листов/несовпадений/selected scope | No silent skip/merge; непредставимое явный отказ |
| CSV с delimiter/encoding ambiguity | Явный UTF-8 strict либо выбранный encoding, separator, header rule | Битые байты/невозможный encoding не заменять U+FFFD молча |
| Формулоподобный CSV text | Текст идёт в DB как text, будущий CSV-export может использовать защитный prefix | Не путать формулу с содержимым БД; export round-trip может отличаться побайтно |

## 4. Приёмка с измеримым результатом

| ID | Сценарий | Проходит, если |
| --- | --- | --- |
| UX01 | Новый пользователь запускает приложение и отменяет welcome | Нет созданной user DB, режим Simple/Advanced сохраняется |
| UX02 | Выбирает отсутствующий SQLite на «Открыть» | Нет файла после ошибки; есть возврат к выбору |
| UX03 | Выбирает ordinary SQLite | Не появляется smartsql metadata/managed migration |
| UX04 | Выбирает managed legacy | Перед upgrade виден version/verified copy path по M01.02; открыт safe flow |
| UX05 | Указывает недоступный PG endpoint | Понятная ошибка и retry, не утверждается что он открыл пустую таблицу |
| UX06 | Создаёт первый проект без сервера | Выбранный путь существует; затем открывается снова; не требуется Интернет/админ |
| UX07 | Предлагает XLSX с 3 листами | Preview показывает все листы и их выбор; no silent drop |
| UX08 | Значения 00123, >15-digit, date-time, formula, NULL/empty/whitespace | Raw/effective/potential loss видны; без подтверждения нет записи |
| UX09 | Cancel/error до commit импорта | Destination не изменился, нет полупроекта |
| UX10 | Повторный запуск, recent project отсутствует | Не создаётся новый DB на том же пути |
| UX11 | Gray/Light, Simple/Advanced, SQL tab/Native Session | Тема/режим не меняют права, не стирают текущую работу |
| UX12 | Min-size Windows, 125/150/200% DPI | Все критические controls видны/доступны с клавиатуры, без обрезания |
| UX13 | Narrator/keyboard/IME и dialog navigation | Порядок фокуса, имена кнопок/ошибок осмысленны, закрытие действует |
| UX14 | Offline/existing corporate read-only connection | Не навязывается cloud, не предлагаются бессмысленные права записи |
| UX15 | «Где данные?»/«Мои копии?» | Видны конкретный root/внешний путь, last verified copy/status, а не фраза «всё сохранено в облаке» |

Модель A/B/C — сценарии проверки, **не** статистика реальных интервью. Не заявлять проценты успешных пользователей без самостоятельного исследования.

## 5. UI статусы для M07 (будущие, не рисовать как работающие сейчас)

- «Сохранено в базе» — только после confirmed DB commit.
- «Локальная копия проверена» — после F2 локального snapshot; показывает источник/время/scope.
- «Google: ожидает отправки» / «Яндекс: ошибка входа» — отдельные per-account statuses.
- «Google: файлы копии проверены» — после F3 remote bytes verification, **не** F4 restore.
- «Восстановление проверено в новый файл» — только после F4.
- «Автокопирование работает, пока SmartSQL открыт» — явно раскрыть условие, если когда-либо M07 v1 готов.

Кнопка/индикатор в верхнем правом углу **не** выталкивает pinned mode/theme controls или OS native caption buttons. На узком окне допускается компактный раскрываемый пункт с клавиатурным доступом.

## 6. Что Codex не должен делать по этому исследованию

- Не перерисовывать всю оболочку ради welcome; M03/M04 после сохранности M01, restore после M05.
- Не внедрять новые DBMS, AI, облака, собственный SQL engine/сервер «для удобства».
- Не менять пустоту/NULL/whitespace в Domain или существующей v3 без отдельного совместимого решения/миграции/тестов.
- Не смешивать Excel workbook, SQLite backup, PostgreSQL dump и CSV export.
- Не заявлять мобильную/другую OS/DPI acceptance по тесту одного Windows Debug.
