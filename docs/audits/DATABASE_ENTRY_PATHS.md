# Вход в SmartSQL: клиент, сервер и выбор базы

Проверено 16 октября 2026 по текущим исходникам и официальным источникам. Это исследовательский аудит и предложения для onboarding; приложение и WORK_PLAN этим файлом не изменены. Последнее уточнение пользователя: Google Диск/Яндекс Диск, автоматические копии и восстановление приоритетнее дальнейшего расширения СУБД; нужен доступный путь совместной работы через сервер. MySQL/MariaDB, затем SQL Server остаются будущими провайдерами.

## Что установить сейчас

| Сценарий | На компьютере пользователя | Где находится СУБД | Дополнительно не требуется |
| --- | --- | --- | --- |
| Локальный проект SmartSQL | Windows x64 self-contained поставка, доступная для записи папка данных на D: | SQLite встроен в приложение | SQLite server/CLI, другой GUI-клиент, .NET SDK |
| Существующий SQLite-файл | Та же поставка, доступ к файлу и согласованный режим открытия | Локальный файл и необходимые WAL/SHM | PostgreSQL или импорт чужой базы в проект SmartSQL |
| Удалённый PostgreSQL | Та же поставка; адрес, порт, база, пользователь, пароль, TLS; корпоративный сетевой доступ при необходимости | Уже обслуживаемый сервер организации/провайдера | Локальная служба PostgreSQL, pgAdmin, psql, ODBC/JDBC |
| Свой локальный PostgreSQL | SmartSQL и отдельно установленный/настроенный PostgreSQL server | Этот компьютер | pgAdmin как обязательная часть работы SmartSQL |
| Команда в локальной сети | На каждом ПК — SmartSQL; на одном выделенном существующем ПК — PostgreSQL | Обслуживаемый ПК в LAN, доступный в рабочее время | Отдельный SmartSQL application server |

Основание в коде: Desktop использует `net10.0`; Infrastructure включает `Microsoft.Data.Sqlite.Core 10.0.11`, `SQLitePCLRaw.bundle_e_sqlite3 3.0.5` и `Npgsql 10.0.3`. SQLite вызывает `Batteries_V2.Init()`, PostgreSQL соединяется через Npgsql. Пользователь не подбирает внешние драйверы. См. [Desktop.csproj](../../src/SmartSQL.Desktop/SmartSQL.Desktop.csproj), [Infrastructure.csproj](../../src/SmartSQL.Infrastructure/SmartSQL.Infrastructure.csproj), [SQLite browser](../../src/SmartSQL.Infrastructure/NativeSqliteDatabaseBrowser.cs), [PostgreSQL browser](../../src/SmartSQL.Infrastructure/PostgresDatabaseBrowser.cs).

Self-contained включает runtime приложения, но не PostgreSQL server. Явно выбранная framework-dependent поставка требует .NET 10 x64 Runtime; SDK нужен для сборки. Установщик пока scaffold без собранного ISCC-пакета. Распаковка portable на D: вне исходников и явный DataDirectory описаны в [DELIVERY](../DELIVERY.md). Запускатель и прямой EXE имеют разные документированные пути данных; перенос между версиями не автоматический.

SQLite работает внутри процесса без серверной службы; это соответствует встроенной поставке. Отдельно скачивать движок конечному пользователю не нужно. [SQLite serverless](https://www.sqlite.org/serverless.html). Доступ к SQLite-файлу регулируется ОС: серверных ролей и удалённой аутентификации этот путь не добавляет.

## Текущие возможности и ограничения

Функции сверены с кодом и [матрицей](../CAPABILITY_MATRIX.md). HANDOFF фиксирует 614 тестов/60 PostgreSQL facts как результат проверки основного агента; в этом аудите сборка, тесты и UI не запускались. Ручная приёмка T04/T11/T12/T23 открыта.

- Управляемый SQLite-проект: свои таблицы/типы SmartSQL, CRUD/структура/фильтры, backups, CSV/JSON/XLSX/clipboard. Это отдельный сценарий от открытия произвольного файла.
- Обычный SQLite: каталог/страницы/типизированный поиск/инспектор; исходно чтение. Отдельное включение допускает подтверждённый single-cell UPDATE с обязательной предзаписной копией на D:. Сложные таблицы остаются read-only; обычные INSERT/DELETE и миграция чужой схемы не добавлены.
- PostgreSQL: существующие базы, схемы, страницы, фильтры/нативная сортировка, инспектор собственных ограничений/индексов. Отдельное разрешение записи не отменяет независимых проверок UPDATE/INSERT/DELETE, PK, прав и конфликтов. Входящие FK блокируют первый срез удаления.
- SQL-вкладки обычных SQLite/PostgreSQL: независимые сеансы, явный запуск только чтения, отмена и лимиты. SQLite SQL пока UTF-8; просмотр/изменение таблиц UTF-16 — отдельная возможность. SQL-результат не получает edit handles.
- MySQL, MariaDB, SQL Server: рабочих провайдеров/подключений сейчас нет. Совпадение протокола, расширения файла или SQL-диалекта не подтверждает совместимость.
- Инспектор T12 не является полной DDL-выгрузкой или графом зависимостей. Native external exchange, автоматическая синхронизация и перенос произвольной базы между СУБД текущим UI не обещаются.

Корпоративные границы [SQL](../READ_ONLY_SQL.md): read-only PostgreSQL не является ОС-песочницей для функций/расширений. Локальная история хранит до 30 успешных SQL, включая литералы; `.sql` также может содержать чувствительные данные. Пароль подключения в профиле не сохраняется, но это не означает отсутствия секретов в самом введённом SQL.

## Аудитории и безопасный выбор

Выбор зависит от существующей инфраструктуры, совместной записи и ответственного за данные. Ниже потенциальные аудитории, а не утверждение о завершённой отраслевой функциональности.

| Пользователь/задача | Начальный путь | Условие выбора |
| --- | --- | --- |
| Преподаватель, студент, учебная лаборатория | Локальный проект/SQLite для учебного SQL | Синтетические данные/копии; PostgreSQL для изучения серверных ролей/конкуренции |
| Склад, мастерская, каталог оборудования | Локальный проект на одном рабочем месте | Назначен владелец backups; общая многопользовательская запись не требуется |
| Координатор проектов, клиентов, сотрудников | Личный локальный учёт либо PostgreSQL организации | Персональные данные, доступ и сроки хранения согласованы организацией; продукт её политики не заменяет |
| Исследователь, аналитик, контролёр качества | Копия SQLite или SELECT-роль PostgreSQL | Источник/полномочия известны, результаты и SQL сохраняются в разрешённой папке |
| Разработчик, QA, интегратор | Синтетическая SQLite/отдельная PostgreSQL test database | Изоляция от production; полной замены средств администрирования/миграции пока нет |
| Сотрудник с общей БД организации | Уже обслуживаемый PostgreSQL | Администратор выдаёт ограниченную роль, TLS и маршрут; локальный server не дублируется |
| Полевой/офлайн пользователь | Локальный проект/копия SQLite | Предусмотрены backups; синхронизация после подключения не подразумевается |
| Пользователь MySQL/MariaDB/SQL Server | Пока текущий утверждённый клиент | Дождаться провайдера, не менять движок только ради текущего SmartSQL |

SQLite подходит локальным приложениям и файлам. Для множества клиентов общей сетевой базы официальный SQLite рекомендует клиент-серверную СУБД и отмечает проблемы блокировок сетевых файловых систем. Общий SQLite-файл в сетевой/синхронизируемой папке поэтому не предлагается как серверный режим SmartSQL. [SQLite: appropriate uses](https://www.sqlite.org/whentouse.html).

### Доступная совместная работа и облачные копии

Для небольшой команды самый доступный по дополнительному оборудованию вариант может быть **существующий ПК в LAN как PostgreSQL host, остальные ПК — клиенты SmartSQL**. PostgreSQL Community не требует покупки серверной лицензии по PostgreSQL License; это не нулевая стоимость эксплуатации. Владелец обеспечивает включённый ПК, обновления, права, сеть, дисковое пространство, копии и проверку восстановления. Сон/выключение/поломка этого ПК останавливают доступ команды. Совместная работа здесь означает доступ разных прямых клиентов к серверной базе с транзакциями и действующими проверками конфликтов; presence, чат и синхронное редактирование документа SmartSQL не добавлены. [PostgreSQL License](https://www.postgresql.org/about/licence/).

Для удалённых участников возможен обслуживаемый сервер либо доступ через согласованный VPN к LAN-host. Стоимость, SLA, сетевой маршрут, TLS, хранение персональных данных и ответственность за backup выбираются по условиям организации/провайдера; бесплатность хостинга и готовность такой инфраструктуры не обещаются. Выделенный **SmartSQL application server не является предпосылкой**: текущее приложение напрямую подключается к PostgreSQL. Развёртывание отдельного серверного продукта SmartSQL этим предложением не вводится.

Google Диск и Яндекс Диск — приоритетные будущие места **готовых проверенных копий**, а не серверы PostgreSQL и не механизм одновременной записи в один SQLite-файл. Автоматическое облачное копирование/восстановление в текущем SmartSQL ещё не реализовано. До такого среза проверяются согласованное создание снимка активной базы, версия/целостность, успех загрузки, удержание копий, доступ к аккаунту и восстановление в отдельную локальную папку. Серверный PostgreSQL backup требует своего согласованного серверного способа; копирование его работающего каталога как обычной папки не предлагается.

Если команда обменивается облачными SQLite-снимками, допустим только явно организованный **поочерёдный один редактор**: закончить изменения, сформировать согласованную копию, подтвердить передачу, затем следующему участнику открыть отдельную локальную копию. Конфликтующие версии не сливаются автоматически; нельзя считать этот порядок онлайн-командной работой. Автоматического захвата роли редактора или протокола передачи в продукте сейчас нет.

## PostgreSQL: клиент отдельно от сервера

Для существующего сервера запросить у администратора DNS-имя, порт, database, отдельную роль, разрешённые схемы, TLS/CA и сетевой маршрут. 5432 — порт по умолчанию, фактическое значение задаёт администратор. Серверу нужны соответствующие `listen_addresses`, `pg_hba.conf` и сетевые правила. SmartSQL их не меняет. Ограничивать источники нужными клиентами/VPN, не открывать server всему Интернету ради подключения. [Connections](https://www.postgresql.org/docs/current/runtime-config-connection.html), [pg_hba.conf](https://www.postgresql.org/docs/current/auth-pg-hba-conf.html).

Для нового локального стенда использовать [официальную страницу PostgreSQL Windows](https://www.postgresql.org/download/windows/), направляющую к установщику EDB. Создание server/cluster/role/database отдельно выполняет ответственный владелец; это не действие кнопки подключения. В проекте пути данных/тестовых артефактов остаются на D:. Upstream поддерживаемую ветку проверять по [versioning policy](https://www.postgresql.org/support/versioning/); она не является матрицей сертифицированных SmartSQL версий. Один проверенный fixture не подтверждает все версии/расширения.

Новый профиль в [ConnectionsDialog](../../src/SmartSQL.Desktop/Views/ConnectionsDialog.cs) выбирает VerifyFull. Для удалённой БД нужны проверка цепочки и имени сервера; Require шифрует без проверки имени, Prefer допускает отсутствие TLS. При ошибке сертификата согласовать DNS/CA, а не снижать защиту до Disable. В профиле нет отдельных полей custom CA, client certificate, SSH tunnel, SSO/MFA или автоматического token refresh; совместимость такой среды проверять отдельно. GSS encryption явно отключён в ConnectionSettings. [Npgsql security/TLS](https://www.npgsql.org/doc/security.html).

Первое подключение — без editing, с серверной ролью наименьших прав: CONNECT, нужный schema USAGE и SELECT на согласованных объектах. Owner/superuser для обычного просмотра не нужен. Недоступность может отражать права/RLS; отсутствие в каталоге не доказывает отсутствие объекта на сервере. Позже права записи выдаются адресно, а допустимость каждой операции приложение проверяет отдельно.

## Короткие onboarding flows и acceptance

1. **Нет своей СУБД:** распаковать self-contained на D:, запустить с явным DataDirectory, выбрать режим, создать проект/демо. Проверить работу без server/сети/SDK, сохранение после перезапуска и изоляцию от исходников.
2. **Есть SQLite:** открыть обычную базу на согласованной копии, проверить структуру, NULL/тип/фильтр. Проверить отсутствие миграций/служебных таблиц, выключенную запись, корректное сохранение WAL при подготовке копии.
3. **Есть PostgreSQL:** получить endpoint/роль/TLS, заполнить профиль, подключиться без editing. Проверить database/schema/identity, сертификат, ограничения прав, отсутствие пароля в профиле, освобождение вкладок при отключении.
4. **Нужна запись:** отдельная синтетическая база, явное разрешение, одна подтверждённая ячейка. Проверить отказ для неподдерживаемой структуры, конфликт без перезаписи и отсутствие автоматического повтора после отмены/unknown COMMIT; для SQLite — mandatory prewrite backup.
5. **Корпоративный/offline ПК:** IT выдаёт поставку/сертификаты/папку/маршрут. Проверить отсутствие загрузки драйверов при запуске, локальную работу без сети. Удалённый SQL требует доступности server; offline-cache не обещается. Другой GUI и глобальная перенастройка пользователя не являются требованием.

Это предложенные проверки, не отметки новой ручной приёмки. Рекомендации UI: объяснить «локальный файл / существующий сервер», отделить установку server от подключения, показать требования роли/TLS до подключения и явно пометить будущие СУБД. Реализация в этот аудит не входит.
