# Просмотр обычных SQLite-баз

Команда **База → SQLite-файл для просмотра…** открывает обычный существующий `.db`, `.sqlite` или `.sqlite3` через общий обозреватель. Создавать служебные метаданные SmartSQL или мигрировать исходный файл не требуется. Локальный редактор SmartSQL-проектов остаётся отдельным процессом.

Обозреватель показывает объекты схемы `main`, структуру и страницы по 100 строк. Доступны буквальный поиск, [условия по типам и нативная сортировка](NATIVE_QUERIES.md) до пагинации, обновление, отмена и полное значение по двойному щелчку. Режим — чтение; вставка/изменение/удаление обычных SQLite-строк пока не реализованы.

## Нативные значения и границы

- SQLite допускает разные классы хранения в одном столбце. Объявленный тип не гарантирует фактический тип всех значений. Вкладка структуры показывает объявленные типы и подтверждённый PK.
- INTEGER читается как точное 64-битное число. REAL — как нативный double с обратимым текстовым представлением; это не произвольная десятичная точность. TEXT сохраняет NULL/пустую строку/пробелы; BLOB показан как `0x` и hex.
- Поддерживаются UTF-8, UTF-16le и UTF-16be источника. Некорректная кодировка TEXT отклоняется явно; замены символов или обрезания нет.
- Таблицы и представления читаются без метаданных SmartSQL. Виртуальные и служебные shadow-объекты могут быть видны в каталоге, но их структура/данные отклоняются с объяснением текущего ограничения.
- Поиск `lower` обрабатывает ASCII-регистр. Выбранная сортировка использует нативные классы хранения, NULL первыми; REAL-представление SQL для поиска может отличаться от отображаемого double. Типизированные сравнения проверяют весь затронутый столбец в одном снимке; несовместимые значения вне страницы также вызывают явный отказ.
- Каждая страница — отдельный снимок. Отсутствующий или допускающий NULL ключ не гарантирует устойчивый порядок при параллельных изменениях; это отмечено диагностикой.
- Лимиты: API до 500 строк, страница объекта до 600 столбцов, значение до 1 млн символов, страница до 16 млн; превышение отклоняется явно. Структура широкого объекта доступна отдельно. Чтение ограничено по времени и поддерживает отмену.

## Живой WAL и чтение

Соединение использует ReadOnly, `query_only`, отключённые расширения и `trusted_schema`. Файл не получает пользовательские изменения, служебные таблицы SmartSQL или checkpoint от обозревателя. Режим `immutable` не используется: он мог бы скрыть актуальные записи живого WAL.

Движок SQLite может использовать или создавать служебные `-shm`/`-wal` рядом с исходной базой даже при чтении. Это прямо указано в диагностике; чтение не называется побитовой копией всех служебных файлов или резервной копией базы. Все создаваемые тестовые источники и результаты остаются в `.workspace` на D:.

Проверки охватывают обычные базы без SmartSQL, Unicode/кавычки, составные ключи WITHOUT ROWID, типы/NULL/пустоту/BLOB, страницы/поиск/сортировку, кодировки, отмену/закрытие, лимиты и сохранение main/WAL при чтении живой базы. Ручная приёмка нового окна остаётся в [T04](TASKS.md).
