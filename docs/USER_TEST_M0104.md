# Ручная проверка M01.04 — единое хранилище preview.9

Эта проверка занимает примерно 10–15 минут. Итоговая сборка: `D:\Code\SmartSQL-builds\0.7.0-preview.9\win-x64-self-contained-verified-m0104-20261017\app` (preview.9; manifest/checksum будут сверены перед передачей).

После публикации сборка содержит portable-marker рядом с EXE. Поэтому прямой запуск `SmartSQL.Desktop.exe` и запуск `Run-SmartSQL.ps1` должны использовать один и тот же выделенный root:

`D:\Code\SmartSQL-user-tests\m0104`

Это свежий тестовый root. Не переносите в него старые базы и не удаляйте существующие рабочие файлы. Перед каждым следующим запуском полностью закройте SmartSQL: один root рассчитан на один активный экземпляр приложения в этой проверке.

`Run-SmartSQL.ps1` — вспомогательный скрипт разработки и приёмки: он по-прежнему разрешает путь к сборке и явный `-DataDirectory` только в именованном каталоге на D: без reparse point. Это ограничение скрипта, а не продукта. В обычной пользовательской поставке без portable-marker прямой запуск EXE использует стабильный product default в Windows LocalAppData либо ранее выбранный root; диск D: конечному пользователю не требуется. В этой preview-сборке packaged marker намеренно направляет оба способа запуска в указанный тестовый root на D:.

## Приоритетный чек-лист

1. Откройте итоговую папку сборки и запустите `SmartSQL.Desktop.exe` напрямую. Если появится первый выбор режима, выберите **Простой**.

   Ожидается: приложение открывается без консольного окна; в интерфейсе или статусе показан root `D:\Code\SmartSQL-user-tests\m0104`; системные кнопки свернуть, развернуть и закрыть видимы и работают.

2. Создайте демонстрационный проект либо новый проект только на синтетических данных. Например, создайте таблицу `Contacts` с полями `Name` типа **Текст** и `Amount` типа **Число**, затем добавьте строки `Анна / 10` и `Борис / 25`.

   Ожидается: проект и обе строки создаются без ошибки; текст и числа отображаются в своих полях. Не используйте реальные имена, контакты, пароли или другие личные данные.

3. Смените светлую/серую тему и переключите глобальный режим на **Расширенный**, затем верните удобный режим при желании. Закройте приложение обычной кнопкой окна.

   Ожидается: тема и режим меняются сразу; окно закрывается штатно.

4. Для проверки второго способа запуска откройте установленный PowerShell 7 и выполните команду ниже. Обычный запуск EXE не требует PowerShell и остаётся главным способом; двойной щелчок по .ps1 может открыть редактор, а не приложение. JSON вручную не редактируйте.

   ```powershell
   pwsh -NoProfile -File 'D:\Code\SmartSQL-builds\0.7.0-preview.9\win-x64-self-contained-verified-m0104-20261017\app\Run-SmartSQL.ps1'
   ```

   Ожидается: приложение снова показывает тот же root `D:\Code\SmartSQL-user-tests\m0104`; выбранные тема и режим сохранились; если проект не открылся автоматически, нажмите «Открыть проект…» и выберите ранее сохранённый синтетический файл; таблица `Contacts` содержит `Анна / 10` и `Борис / 25`.

5. Закройте приложение и ещё раз запустите `SmartSQL.Desktop.exe` напрямую. Создайте второй синтетический проект или откройте первый через штатную команду повторного открытия.

   Ожидается: после смены способа запуска root не меняется; новый проект создаётся, а существующий открывается из прежнего места без копирования или исчезновения данных.

6. В отдельном действии выберите обычный внешний файл SQLite через отдельную кнопку подключения SQLite, не через создание управляемого проекта.

   Ожидается: подключение открывается отдельно от управляемого проекта и только для чтения; оно не подменяет управляемый проект и не делает скрытого переноса файла в product root. Для этой проверки не изменяйте внешний файл.

7. Проверьте итог: путь root в интерфейсе/статусе всё ещё равен `D:\Code\SmartSQL-user-tests\m0104`, тема и режим пережили перезапуск, оба способа запуска видят один проект и одни данные, системные кнопки окна остаются доступными.

## Если что-то не совпало

Закройте приложение и передайте:

- номер шага и точную последовательность действий;
- фактический путь root, показанный приложением;
- ожидаемый и фактический результат;
- снимок экрана ошибки или неверного состояния;
- текст ошибки без учётных данных, токенов, строк подключения и личных данных.

Не редактируйте `smartsql.portable.json` и не удаляйте реальные файлы для диагностики. Эта ручная проверка подтверждает только единый root, сохранение локальных настроек/синтетического проекта и базовый запуск preview.9. Она не подтверждает облачную доставку, новую DBMS, AI-функции или миграцию старых данных. Автоматические тесты отдельно не считаются выполненной ручной приёмкой.

## Что важно понимать

SQLite встроен: для этой проверки сервер, SQL и отдельный редактор БД не нужны. Данные записываются локально в файл; автосохранение не означает облачную копию. При первом входе в новую папку может быть пустой стандартный проект — это нормально. Демонстрация создаёт отдельный пример. Именованный проект сохраняйте через «Новый проект…» в тестовую папку и запомните имя: список последних файлов/вкладок пока не восстанавливается автоматически.

Дополнительная безопасная проверка: оставив первое окно открытым, запустите второй EXE. Ожидается отдельное окно понятного отказа для занятого хранилища. Закройте только второе окно, убедитесь, что первое работает; затем штатно закройте первое и откройте приложение снова. Не удаляйте marker, папку или БД для проверки ошибки. Если нужен тест неправильного пути/повреждения, сначала пришлите результат обычных шагов — подготовим отдельный синтетический сценарий.

Если запуск скрипта запрещён локальной политикой, не меняйте глобальные настройки Windows: отметьте этот шаг как «не выполнен» и продолжайте запускать EXE. Скриншот с номером шага, ожидаемым/фактическим результатом и версией preview.9 достаточен; секреты и рабочие данные не прикладывайте.
