# PostgreSQL: просмотр и безопасные операции со строками

В едином рабочем окне откройте подключение PostgreSQL, укажите сервер, порт, базу, пользователя и режим TLS. Сохранение профиля необязательно. Пароль вводится для текущего подключения и не сохраняется; профили находятся в игнорируемом `data/local/connections.json` на D:.

Подключение появляется в общем дереве со схемами, таблицами и представлениями. Таблица открывается в центральной вкладке `DatabaseTableView`: **Данные** показывают страницы по 100 записей, **Структура** — исходные типы, nullable и порядок полей составного первичного ключа. Каждая вкладка владеет отдельной сессией провайдера и состоянием страницы; уникальная идентичность подключения не смешивает одинаковые имена из разных баз. NULL показан приглушённым курсивом; пустая строка и текст `∅` сохраняют отдельное значение. Загрузка отменяется кнопкой или закрытием вкладки.

Поиск слева сокращает список объектов. Поиск над данными применяется ко всей таблице до пагинации: введите буквальный фрагмент и нажмите **Применить** или Enter. Регистр обрабатывается по правилам локали PostgreSQL; локаль C может различать регистр нелатинских букв. [Типизированные AND-фильтры и нативная сортировка](NATIVE_QUERIES.md) применяются до пагинации: 2 меньше 10, NULL первыми. Поддерживаются подтверждённые встроенные типы; domains и прочие типы допускают только NULL-условия. **Сбросить** убирает поиск, фильтры и выбранный порядок.

Двойной щелчок по ячейке открывает полное значение без обрезания. В отдельном окне можно выделить текст или скопировать его целиком; NULL и пустая строка обозначаются отдельно.

## Изменение одной ячейки

При открытии подключения по умолчанию включён режим чтения. Для изменений явно разрешите редактирование в окне подключения. Это разрешение относится только к текущему подключению, не сохраняется в профиле и не заменяет права пользователя PostgreSQL.

Выберите строку и нажмите **Изменить значение**. В диалоге выберите доступный столбец, проверьте исходное и новое значение и сохраните. NULL задаётся отдельной галочкой; снятая галочка и пустой текст означают пустую строку для текстового поля. Пробелы сохраняются. Для чисел используется точка, для дат — `ГГГГ-ММ-ДД`, для Boolean — Да/Нет, true/false или 1/0. Сохранение меняет одну ячейку, затем обновляет текущую страницу.

Перед записью провайдер повторно проверяет структуру, права и исходную строку по полному первичному ключу. Если другое подключение изменило или удалило строку, запись отменяется: обновите страницу, проверьте новые данные и заново выберите изменение. Автоматического повтора нет. Если подтверждение COMMIT не получено, результат обозначается как неизвестный; сначала обновите данные и проверьте значение.

Разрешение строки хранится только в памяти провайдера и действует для текущей страницы не дольше 15 минут. Обновление страницы, каталога или структуры, а также успешная запись требуют нового чтения. Ключи, уникальные, автоматические и вычисляемые поля защищены. Причины ограничений видны во вкладке **Структура**.

Поддерживаемые поля первого этапа: встроенные `text`, `varchar`, `smallint`, `integer`, `bigint`, `numeric`, `date`, `boolean`. Округление `numeric`, переполнение или обрезание строки отменяют транзакцию; большие числа не проходят через ограниченный .NET `decimal`. Остальные нативные типы сохраняют возможность просмотра.

Числовой ввод ограничен 1024 символами записи; более длинные нативные числа доступны для просмотра. Ввод даты ограничен годами 0001–9999 в указанном ISO-формате; нативные бесконечные даты и даты вне этого диапазона пока доступны для просмотра. Ограничения отмечаются в диагностике объекта.

## Добавление одной строки

Откройте подключение с явным разрешением записи, выберите таблицу и нажмите **+ Новая запись**. Для каждого поля доступны только подтверждённые способы: **Заполнит сервер**, явный **NULL**, **Указать значение**. Пустой текст в режиме значения означает пустую строку, пробелы сохраняются. Identity/generated поля заполняет сервер; поддерживаемые ключи и уникальные поля можно задать при создании, хотя они защищены от изменения уже существующей строки.

Серверные DEFAULT не исполняются произвольно: небезопасное выражение запрещено; поддерживаемое поле можно заполнить явным значением. Неподдерживаемое обязательное поле без безопасного DEFAULT блокирует создание. Вставка возвращает нативные значения и проверяет точность до COMMIT. Ошибка откатывает строку; неизвестный COMMIT требует проверки данных без повторной отправки.

Нужны SELECT/INSERT и право защитной блокировки: MAINTAIN на PostgreSQL 17+ либо UPDATE/DELETE/TRUNCATE. Клиент не выдаёт эти права автоматически. Sequence/identity требуют подтверждённого доступа к принадлежащей полю последовательности. Номер последовательности не откатывается: после ошибки/отмены возможны пропуски ID, даже когда строка полностью откатилась.

## Удаление одной строки

В подключении с явным разрешением записи выберите строку и нажмите **Удалить строку**. Подтверждение показывает базу, схему, таблицу, составной первичный ключ и предпросмотр данных. Для отправки нужно отдельно отметить подтверждение; отмена диалога ничего не удаляет. Длинные значения сокращаются только в предпросмотре.

Нужны независимые SELECT/DELETE-права; UPDATE не требуется. Операция повторно проверяет структуру, права, связи, полные исходные значения и версию строки под защитной блокировкой. Удаляется ровно одна подтверждённая строка, иначе транзакция откатывается. Разрешение удаления отдельное, одноразовое и относится только к текущей странице до 15 минут. После отправленной попытки, в том числе ошибки/отмены, обновите страницу и выберите строку заново.

Первый срез запрещает **любой входящий FK**, включая самоссылку, RESTRICT/NO ACTION, CASCADE, SET NULL и SET DEFAULT. Исходящий FK сам по себе не мешает удалить дочернюю строку. Защищены также представления, таблицы без надёжного ключа, наследование/секции, RLS, пользовательские триггеры, DELETE-правила и небезопасные выражения/вывод типов. Причина запрета показана в диагностике; каскадное удаление не выполняется.

При конфликте или отмене автоматического повтора нет. Если COMMIT не подтверждён, результат неизвестен: обновите данные и проверьте строку перед новым действием. Успешное удаление и ошибка последующей загрузки страницы обозначаются отдельно. После удаления единственной строки последней непервой страницы открывается предыдущая. Внешнее удаление не имеет общей отмены или автоматической резервной копии.

## Границы текущего этапа

- Внешняя PostgreSQL-база открывается без метаданных SmartSQL в общей оболочке. Управляемый SQLite-редактор использует отдельный адаптер и правила, но встроен в то же окно.
- Открытые вкладки и пароли не восстанавливаются после перезапуска. Глобальный Simple/Advanced — только режим представления; он не выдаёт разрешение записи. SQL-вкладок пока нет.
- Значения читаются как текст PostgreSQL без преобразования в `decimal`/.NET-типы. Большие числа, массивы, JSON, enum и binary сохраняют представление сервера. Timestamp with time zone показан в UTC.
- Каждая страница — отдельный снимок. Изменения базы могут сдвигать записи между страницами. Отсутствие подтверждённого ключа, наследование, RLS и прочие ограничения показываются явно.
- Тайм-аут подключения/команды — 15 секунд. Каталог ограничен 10 000 объектов, API — 500 строк. Значение свыше 1 млн символов или страница свыше 16 млн отклоняются явно без обрезания.
- Изменение доступно обычным таблицам с подтверждённым первичным ключом поддерживаемого встроенного типа и правами SELECT/UPDATE. Представления, таблицы без ключа, наследование, секционирование, RLS, пользовательские триггеры, правила UPDATE и небезопасные функции CHECK/вывода типов остаются доступными для просмотра.
- Удаление при входящих FK, массовое добавление внешних строк, произвольный SQL, отмена внешней записи и внешний обмен остаются следующими этапами. Локальные копии SQLite не являются копиями PostgreSQL.
- Профили разных процессов пока сохраняются по правилу последней записи. Повреждённый JSON не сбрасывается автоматически; после ошибки загрузки сохранение/удаление блокируются.

## Интеграционные тесты

Текущий код проверен на PostgreSQL 17.2: Debug-сборка без предупреждений и **461 тест** приложения (Domain 1, Application 117, Infrastructure 334, Desktop 9), включая **45 реальных PostgreSQL-проверок**, без пропусков. Автотесты оболочки дополнительно покрывают идентичность подключений, независимые сессии вкладок и отмену незавершённой загрузки. DELETE проверяет отдельные права без UPDATE, точные составные ключи, изменения/удаление/ABA, одноразовые разрешения после конфликта/отмены, запреты FK/триггеров/правил/RLS/наследования/секций и реальную блокировку конкурентного ADD FK. Неизвестный COMMIT проверен ревью без имитации сетевого разрыва. Self-contained приложение запущено и частично проверено на SQLite-фильтрах; PostgreSQL UI T04 и [приёмка оболочки](WORKSPACE_UI_ACCEPTANCE.md) открыты.

Обычный `scripts/Test.ps1` явно пропускает интеграционные PostgreSQL-факты, пока не включено тестовое окружение. Они обращаются только к `127.0.0.1:15432`, базе `smartsql_browser_test`, пользователям `smartsql_browser_reader` и `smartsql_browser_editor`. Тесты записи создают и удаляют собственные уникальные таблицы в схеме `smartsql_edit_test`. Фикстуры содержат синтетические данные; используйте отдельный новый кластер, а не рабочую базу.

```powershell
. ./scripts/Initialize-Workspace.ps1 -ForTests
$pgTestBin = 'C:\Program Files\PostgreSQL\17\bin'
$pgTestData = 'D:\Code\SmartSQL\.workspace\postgresql-tests'
# initdb применяется только к новому пустому каталогу.
& "$pgTestBin\initdb.exe" -D $pgTestData -U smartsql_test_admin --auth-local=trust --auth-host=trust --encoding=UTF8 --locale=C
& "$pgTestBin\pg_ctl.exe" -D $pgTestData -l "$pgTestData\server.log" -o '-p 15432 -h 127.0.0.1' -w start
& "$pgTestBin\psql.exe" -h 127.0.0.1 -p 15432 -U smartsql_test_admin -d postgres -v ON_ERROR_STOP=1 -f tests/SmartSQL.Infrastructure.Tests/Fixtures/PostgresCreate.sql
& "$pgTestBin\psql.exe" -h 127.0.0.1 -p 15432 -U smartsql_test_admin -d smartsql_browser_test -v ON_ERROR_STOP=1 -f tests/SmartSQL.Infrastructure.Tests/Fixtures/PostgresBrowser.sql
& "$pgTestBin\psql.exe" -h 127.0.0.1 -p 15432 -U smartsql_test_admin -d smartsql_browser_test -v ON_ERROR_STOP=1 -f tests/SmartSQL.Infrastructure.Tests/Fixtures/PostgresEditing.sql
$env:SMARTSQL_POSTGRES_TEST_PORT = '15432'
./scripts/Test.ps1 -Offline
& "$pgTestBin\pg_ctl.exe" -D $pgTestData -w stop
Remove-Item Env:SMARTSQL_POSTGRES_TEST_PORT
```

Для уже подготовленного кластера не повторяйте `initdb`, создание базы или `PostgresBrowser.sql`. Новая `PostgresEditing.sql` добавляет отдельную схему и тестовую роль в эту же одноразовую базу.

Trust используется только в одноразовом loopback-кластере. Существующий сервис PostgreSQL не меняется; установленный runtime остаётся на своём месте, все данные/журналы/результаты на D: и вне Git. Проверяются права, составной ключ, страницы/граница, 60-значное число, NULL/пустота, native-типы, кавычки/Unicode, режим чтения, отмена/освобождение и слишком большие значения. Проверки записи дополнительно покрывают откат округления, изменённые/удалённые строки, защищённые столбцы, ограничения структуры и недействительные разрешения строки.
