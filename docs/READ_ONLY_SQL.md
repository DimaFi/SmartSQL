# SQL только для чтения — первый срез T11

В расширенном режиме кнопка **SQL…** открывает независимую вкладку выбранного обычного SQLite- или PostgreSQL-подключения. Несколько SQL-вкладок имеют разные номера и собственные текст, результат и сеанс. Для управляемого проекта SmartSQL SQL пока не предоставляется. При переходе в простой режим открытая вкладка сохраняется; права записи таблиц не переходят в SQL.

Запуск — кнопкой или Ctrl+Enter, без автоматического исполнения при открытии файла/истории. Есть отмена, лимит 1–500 строк, общий предел 15 секунд, SQL до 64 КиБ UTF-8, до 600 столбцов, 1 млн символов в ячейке и 16 млн в результате. Лишняя строка подтверждает наличие продолжения; превышение объёма выдаёт ошибку без частичного результата. Перед запуском старый результат очищается. Результаты произвольного запроса не получают фиктивные PK, table identity или edit handles. Дубликаты имён разделяются ordinal; NULL, пустота и полное значение обозначены отдельно.

## PostgreSQL

Каждое выполнение открывает отдельное непулируемое соединение с session default read-only, ограничениями ожидания и явной READ ONLY транзакцией; серверное состояние проверяется до пользовательского SQL. Один `NpgsqlBatchCommand` без параметров отправляется как одна native Parse-команда. SchemaOnly выполняет Parse/Describe без исполнения. Затем native `DECLARE ... CURSOR FOR` допускает запросы SELECT/VALUES/TABLE/WITH, а собственный FETCH читает до лимита плюс одну строку. Ошибка, отмена и завершение освобождают транзакцию/соединение; COMMIT не применяется.

Через публичный `AllResultTypesAreUnknown` результат FETCH приходит точным текстом PostgreSQL: numeric не округляется до .NET decimal, bytea/JSON/массивы/даты остаются серверным представлением. Timezone сеанса UTC. SHOW, EXPLAIN, CALL, bind-параметры, ручные транзакции и SQL-запись в первый срез не входят. SQLSTATE используется для безопасной диагностики; SQL, пароль и подробности драйвера не включаются в ошибки.

Read-only не является ОС-песочницей: пользовательские функции/расширения могут иметь внешние эффекты. Настройки, изменённые функцией только в одном SQL-сеансе, не передаются следующему запросу. Проверка первого слова, собственный SQL lexer и удаление разделителей команд не используются.

## SQLite

Отдельное ReadOnly-соединение, `query_only`, `trusted_schema=OFF`, defensive mode, отключённые extensions и временное хранение в памяти. Каталог обычных main-таблиц/представлений читается в том же read-снимке. Native authorizer разрешает только SELECT/подтверждённые READ, рекурсию и ограниченный список встроенных функций; DML/DDL, PRAGMA, ATTACH/DETACH, ручные транзакции и неизвестные функции запрещены. Native prepare с NO_VTAB также исключает виртуальные таблицы; shadow-объекты не входят в список разрешённых. Весь SQL-tail разбирается до первого step: требуется ровно один непустой readonly statement с результатом и без параметров.

При чтении без столбцов SQLite иногда передаёт READ с пустым столбцом и без схемы. Такой READ разрешён только для точного имени уже подтверждённого обычного main-объекта. Неизвестные имена CTE остаются закрыты: например, `WITH n AS (...) SELECT count(*) FROM n` может быть отклонён; выбирайте явный столбец, например `count(id)`. Виртуальные/shadow/temp-подсчёты закрыты. Расширение на произвольные неподтверждённые имена не принято.

Первый SQL-срез поддерживает **UTF-8 SQLite**. UTF-16 явно отклоняется только SQL-исполнителем; просмотр и безопасное изменение таблиц UTF-16 остаются доступны. INTEGER читается как Int64, REAL как обратимый double, BLOB как hex, TEXT — строгим UTF-8 с явной длиной, включая NUL. Некорректные байты не заменяются символом подстановки. Connection-local limits, progress handler и interrupt ограничивают выполнение; общая память процесса и ОС не объявляются изолированными. WAL может требовать служебные SHM/WAL, миграций/checkpoint нет.

## Локальная история и файлы

В `data/local/queries/history.json` выбранного runtime-каталога остаются последние 30 успешных запросов всех подключений. Повторы SQL для одного имени подключения/провайдера перемещаются в начало. Сохраняются SQL, время, несекретное имя подключения, провайдер и число строк; результаты и пароль профиля не записываются. Сам SQL может содержать введённые пользователем значения — локальность явно указана в UI. История ограничена по размеру, запись атомарна; повреждённый файл не затирается автоматически, ошибка истории не скрывает успешный запрос. В Git история не включается.

Через файловые диалоги можно открыть/сохранить `.sql` в строгом UTF-8 (BOM при чтении допустим). Файл ограничен 64 КиБ, сохранение атомарно. Открытие и выбор из истории лишь заполняют редактор, затем нужен отдельный запуск.

## Проверка и оставшаяся работа

Автопроверки покрывают обе реальные SQLite/PG реализации: native parsing/несколько команд, CTE-запись, ограничения доступа и временных объектов, точность, NULL/пустоту/Unicode, отмену/дренирование/закрытие, результат/файлы/историю и восстановление после ошибки. SQLite-файлы и все временные результаты на D:; PG — только выделенный loopback-кластер.

Ручная приёмка частичная: SQLite запрос по синтетическим items возвращает 201–205, NULL/пустоту и точный Int64; Ctrl+Enter, сохранение при смене режима, история без автозапуска, таймаут 15 секунд и успешный SELECT 42 после него подтверждены. Тестовое окно закрыто; код выхода отдельно не измерялся. Кнопка отмены в UI пока не принята: при попытках срок истёк раньше подтверждения нажатия; провайдерная отмена проверена тестами. SQL-файлы в UI, несколько SQL-вкладок, PostgreSQL UI, закрытие во время операции, полный cell dialog, DPI/Narrator и visual polish открыты. Редактор пока обычный многострочный TextBox: подсветка/форматирование и дальнейшее удобство редактора — следующий небольшой срез T11 перед полным закрытием задачи.
